## 2. 主 Agent 验收判断

### 2.1 状态机与事实优先级

- merge receipt/source merged/commit oid 任一权威事实均高于 Task projection。
- protocol V2 的 runtime 完成不会自行推进业务状态；必须提交合法 Resolution。
- terminal、merged、blocked、integration purpose、advisory capability 均由统一 guard 约束。
- 合法幂等 replay 在可变状态检查前返回原 Execution；不同 id/run 键命中不同对象时拒绝。

### 2.2 并发与事务

- Task→Source/Attempt→Execution 锁序已统一。
- merge provider 调用前后均有主体重验证；未知结果走持久化 reconcile。
- remediation pointer 与 attempt 原子写入，不再用 `ON CONFLICT DO NOTHING` 静默分叉。
- continuation 在 waiting execution 下保留等待态，在取消竞态下可正确收敛到复核态，并尊重用户后续显式保留的 blocked。

### 2.3 产品语义

- `advisory` 无 branch/PR，完成后直接 done。
- delivery 仍保留 PR 与 reviewed subject 门禁。
- integration blocked 恢复要求用户选择具体 `needs_human` 来源，不默认全选。
- canceled source 是可导航历史，不再阻止 delivery 重新进入集成候选。
- Web 将 Task 状态、Execution 技术状态与 Resolution 业务结论分区展示。
- 创建弹窗与后端初始状态契约一致。
- 上游软删除入口与本次工作流按钮、恢复和关系导航兼容。

### 2.4 历史修复

- repair 默认 dry-run，只有 `--apply` 写库。
- merge fact、projection、fence、cancellation outbox 使用同一判定范围。
- remediation 只有存在 approved Resolution 时自动收敛；不确定记录进入人工复核候选。
- legacy Resolution 只迁移唯一可靠绑定项，重复/残缺数据保留异常标记。
- apply 幂等，第二次执行无重复修复。
