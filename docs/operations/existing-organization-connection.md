# 已有组织接入业务系统

## 使用方式

在平台管理的业务系统详情中，先发布版本，再到“接入配置”维护默认服务地址、页面地址和只读诊断配置。随后在“组织接入”选择 Agent 中已有的组织和该组织的有效技术联系人，确认接入。

- 组织可按名称搜索，管理员优先作为联系人候选；不再填写组织 ID、组织名称、管理员手机号、联系人手机号、安装 ID，也不在接入过程中创建组织、账号或赠送积分。
- 组织成员、管理员和权益沿用现有设置。缺少业务系统权益时必须先配置，不能通过接入操作自动扩大权限。
- 默认地址可包含 `{tenantId}`、`{systemId}`；独立部署可在接入时覆盖地址。地址模板不等于外部服务自动具备多租户能力，实际部署仍需与组织绑定一致。
- 一个组织与一个系统只允许一个安装实例；重复接入应打开已有记录。已删除实例不会通过此表单重新创建。
- 凭据领取与确认、域名验证、部署就绪、成员与 Agent 授权、只读诊断仍需逐项完成。选择组织不代表外部服务已部署或验收通过。
- 旧接入执行记录继续使用原恢复接口；新记录按服务端保存的接入信息继续，不接受客户端改写冻结信息。

## 页面与生命周期

详情页复用现有 Tabs 组件，含“版本管理”“接入配置”“组织接入”。切换标签保留接入进度和本次返回的临时领取信息。

“更多操作”内包含：

- **停用系统**：影响全部已接入组织的工作区入口和新组织接入，可在版本管理中重新发布恢复。各组织的实例状态及授权保持独立。
- **退役系统**：永久退出目录，不可恢复、再发布或新增接入。需要输入系统名称二次确认。

两者均不会删除外部业务数据、关闭外部服务器或代替实例凭据吊销。仅影响一个组织时，应操作该组织的安装实例，不应停用整个系统。

## 数据与发布边界

治理数据库新增 V45 扩展迁移，为系统默认接入配置建立独立表，版本登记的 Manifest 不变。配置保存采用版本号比较更新，变更不会回写已有安装地址；新接入提交必须确认当前配置版本和发布版本。

部署时先通过既有迁移流程升级数据库，再上线服务。回滚应用时保留 V45 表与已有接入记录，不执行删表；旧前端不能恢复新模式记录时，应恢复修复后的前端，不应使用旧创建接口重建组织。

本次仅本地开发及提交；未推送、未创建 PR、未部署，也未更改或运行远程 Workflow。真实外部系统的凭据领取、部署、授权和业务调用仍需后续在明确环境中验收。

## 本地验证（2026-09-08）

- 后端业务系统模块与治理升级：53 个测试文件、327 项测试通过，含新增已有组织接入的 11 项真实 HTTP/PostgreSQL 测试。
- Web 全量 Vitest：357 个文件、2604 项测试通过；共享包：133 个文件、1850 项测试通过。
- 随后补充的默认接入配置 2 项测试通过，涵盖版本号保存、只读诊断选项、参数校验与失败重载。
- 前后端 TypeScript 检查及生产构建通过。Web API 分域检查通过。
- 使用 browser 技能查看本地固定夹具，确认标签样式、组织下拉、默认联系人和地址显示；夹具禁止写请求，不是线上业务验收。
- 全量发布预检未通过：本机为 macOS，发布套件出现缺少 `flock`、GNU tar 参数不支持及 `/dev/full` 不可用等失败。未绕过门禁。
- 后端全量 Vitest 未通过：7367 项通过、801 项失败、48 项跳过、3 项待办，另有 12 个错误。失败包含依赖 Linux `/proc` 的可信文件操作（`ENOTSUP`）及其他模块；未逐项诊断全部失败，也不能将它们全部归因于环境。业务系统与治理升级相关测试独立及全量运行均未出现失败。
- 管理后台契约脚本存在平台页面数量断言失败（实际 13，预期 14）；该脚本与导航注册表均未在本次修改。
- 本机 Node 为 22.21.1，项目要求 22.23.1；完整 Linux CI 仍需在后续授权推送后验证。
