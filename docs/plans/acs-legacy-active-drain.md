# ACS 旧版主动排空兼容升级

生产晋级和兼容部署共用 `scripts/release/acs-deployment-drain.sh`。

## 发布行为

1. 在生产主机锁内核对服务状态、旧进程 PID 和排空协议。
2. 旧版存在在途请求时不再立即拒绝发布；确认尚未排空且计数有效后，发送 SIGUSR2，交由旧进程停止接单并完成已接受的请求。
3. 临时关闭 systemd 自动重启，等待同一个旧进程正常退出。每 15 秒输出等待状态；退出码、退出类型或 PID 不符均拒绝切换。
4. 验证通过后才更新 ACS 文件、配置和服务。忙碌业务沙箱延后换镜像的既有逻辑不变，不批量停止沙箱。
5. 排空失败不兜底强制启动候选版本。清理逻辑恢复原服务策略；旧服务已停止时尝试启动原版本。恢复失败保留证据并要求人工处理。

## 首次升级的边界

旧版 ACS 自身可能在排空超时时异常退出，且不支持取消排空。发布脚本不能改变运行中旧进程的实现，因此首次过渡不能承诺在途任务绝不中断。异常退出会使本次发布失败，不视为排空成功。若旧进程仍在排空，保留现场并报告人工恢复，不强杀。

新版协议支持安全超时、取消排空及零在途任务完成回执；这些校验保持不变。未知协议、无效计数和已经排空中的旧实例均不能直接进入兼容升级。

## 验证

本地模拟覆盖：旧版忙碌后正常排空、空闲升级、旧版超时异常退出、无效健康数据、重复排空、PID 替换、缺失新版回执、新版超时取消，以及函数退出后的生产恢复快照。模拟测试不等同于生产部署或业务不中断验收。
