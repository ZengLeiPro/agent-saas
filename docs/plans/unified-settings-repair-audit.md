## 1. 目标与完成定义

本轮不是只修用户已报告的单点，而是同时完成以下四件事：

1. 所有设置/管理页面使用同一内容坐标系，页头、标签页、提示条、表单和列表左边界一致。
2. 修复已报告功能故障，并沿相同组件、接口、权限链路排查其他页面的同类问题。
3. 隐藏面向实现者的内部术语、版本号和错误码，改成用户能理解且能采取行动的说明。
4. 对设置注册表和管理页面注册表中的每个页面建立按钮清单，逐项点击、保存并回读。

满足以下条件才能从 Draft 转为 Ready：

- [ ] 本文所有 P0/P1 项完成，代码检查和自动化测试通过。
- [ ] 个人设置 8 页、组织/平台管理 31 个导航入口均完成浏览器逐页验收。
- [ ] 每个可见按钮至少覆盖：可点击、禁用原因、成功反馈、失败反馈、刷新后回读。
- [ ] 有写操作的页面使用隔离测试数据；恢复/保存类操作同时验证 API 回读或列表回读。
- [ ] 1366×768、1920×1080、移动断点上下至少各检查一次布局。
- [ ] 未配置的外部能力显示准确的可操作说明，不以超时或内部错误码冒充用户错误。

## 2. 已确认问题与修复任务

### P0：功能不可用或反馈与事实不一致

#### SET-001 我的 Agent 保存返回 409

- 现象：修改 Agent 名称和签名后显示 `Failed to update agent profile: 409`。
- 已确认：前端只拼接 HTTP 状态，丢失服务端错误正文；保存后也没有用服务端结果刷新本地基线。
- 待确认：409 的直接来源是写入安全栅栏、并发版本还是当前账号/组织状态。
- 修复：
  - [ ] 在本地浏览器和 Network 中复现并记录响应正文。
  - [ ] 修正服务端或调用契约，不通过吞掉冲突绕过安全校验。
  - [ ] 共用 API 错误解析，向用户展示中文原因和恢复动作。
  - [ ] 保存成功后使用响应值更新 profile，刷新页面确认名称与签名仍存在。
  - [ ] 覆盖自助编辑、管理员编辑他人、头像上传/重置的同类错误处理。

#### SET-002 回收站恢复“假成功”

- 现象：恢复提示成功，但会话列表找不到恢复的会话。
- 修复：
  - [ ] 复现并绑定具体 sessionId，记录恢复 API、列表 API 和缓存状态。
  - [ ] 检查恢复后列表缓存失效、分页、分组过滤和当前 workspace 投影。
  - [ ] 成功提示必须在权威响应成功且列表回读可见后出现。
  - [ ] 恢复后提供“查看会话”入口；若当前筛选会隐藏它，明确说明并切换到可见位置。
  - [ ] 同时检查彻底删除、批量操作、恢复失败重试。

#### SET-003 组织智能体页面按钮不可点击

- 现象：智能体页面顶部操作按钮均无法使用。
- 初步确认：平台管理员代管组织时组件把 `canEdit` 固定为 false，但页面没有明确解释只读原因，表现为按钮失效。
- 修复：
  - [ ] 分别用平台管理员和组织管理员验证权限语义。
  - [ ] 有合法代管写权限时允许操作；无权限时显示明确只读原因和正确入口。
  - [ ] 检查刷新、创建、模板创建、编辑、启停、头像上传和保存。
  - [ ] 对所有“disabled 但无原因”的管理按钮做同类扫描。

#### SET-004 连接器范围预览依赖不可用

- 现象：点击“预览范围变更”显示 `DEPENDENCY_IMPACT_AUTHORITY_UNAVAILABLE`。
- 已确认：治理路由在未注入 dependency-impact resolver 或 resolver 失败时返回 503；前端直接暴露内部错误码。
- 修复：
  - [ ] 核对本地运行时 resolver 注入缺口，补齐 entitlement/scope 预览的权威依赖。
  - [ ] 依赖确实不可用时保留 fail-closed，但展示中文原因、受影响能力和重试动作。
  - [ ] 覆盖技能、连接器、模型、工具、执行环境等复用范围编辑器的页面。
  - [ ] 预览成功后验证基线、影响数量、提交和刷新回读。

#### SET-005 预算与计费标签页无作用

- 现象：页面顶部 Tab 点击后内容不切换。
- 初步定位：外层路由把“预算与计费”固定带入 `usageSection=billing`，内层组件同时维护自己的 usage/billing Tab，存在路由归一化和受控值互相覆盖。
- 修复：
  - [ ] 明确一个页面只保留一层页面级 Tab。
  - [ ] Tab 点击更新 URL，并在前进、后退、刷新后保持当前视图。
  - [ ] 分别验证“用量看板”和“预算与计费”内容，不允许两个导航入口指向同一固定态。

### P1：权限可发现性与能力配置

#### SET-006 “显示详细执行过程”无法开启

- 当前三层开关链路：平台给组织授权 `debugModeAllowed` → 组织开启 `debugModeEnabled` → 成员开启个人 `debugMode`。
- 修复：
  - [ ] 在禁用说明中直接给出当前缺失层级和跳转入口，不再只说“组织未开放”。
  - [ ] 平台管理员可从组织详情开启“调试模式授权”。
  - [ ] 组织管理员可从“功能与配额”开启“成员调试模式”。
  - [ ] 成员在“对话与模型”或“我的权限”开启个人偏好后，两处状态一致。
  - [ ] 验证关闭上游开关会安全清理下游状态。

#### SET-007 个人调试模式不可开启

- 与 SET-006 共用同一三层权限链路。
- 修复：
  - [ ] 合并重复入口的状态组件和说明口径。
  - [ ] 有管理权限时提供直达配置按钮；普通成员显示应联系的角色。
  - [ ] 不展示内部 entitlement 名称、版本或策略 ID。

#### SET-008 浏览器桌面通知超时

- 现象：开启后等待超时，提示用户检查网络/浏览器设置。
- 待区分：浏览器权限、Service Worker、PushManager、VAPID 服务端配置、localhost 浏览器能力、订阅 API 中的哪一层失败。
- 修复：
  - [ ] 开启前先检查服务端是否配置 Web Push，并在未配置时禁用开关、说明管理员动作。
  - [ ] 将权限拒绝、浏览器不支持、SW 未就绪、PushManager 超时、服务端 503 分开提示。
  - [ ] 避免无边界等待；超时后清理 pending 状态并允许重试。
  - [ ] 验证开启、刷新保持、移除当前设备和多设备列表。

### P1：统一布局与编辑体验

#### SET-009 页面头部与内容左边界不一致

- 截图确认页面：系统提示语。
- 扩散范围：所有由 `ManagementShell` 渲染统一页头、但子组件仍有 `mx-auto/max-w/padding` 的页面。
- 统一规则：
  - [ ] 页面壳唯一负责 `max-w-6xl`、响应式横向 padding 和页头坐标。
  - [ ] 子页面根节点只负责高度、滚动和内部布局，不再二次居中或叠加页级 padding。
  - [ ] 页头、页面 Tab、首个提示/错误块、首张卡片共用同一左/右边界。
  - [ ] 数据密集型页面如确需 full width，必须由注册表显式声明，而不是组件自行漂移。
- 扫描范围：`max-w-*`、`mx-auto`、`px-*`、负 margin、嵌套 `SettingsPanelHeader`、内部 `h1/h2`。

#### SET-010 编辑区太小

- 用户确认页面：我的 Agent、智能体规则、组织资料。
- 同类扫描：Persona、Memory、系统提示语、组织上下文模板、长文本配置。
- 修复：
  - [ ] 名称/签名单行字段使用合理最大宽度，但不缩成窄列。
  - [ ] 长文本编辑器使用可用剩余高度，设置合理 `min-height`，允许垂直调整或全屏编辑。
  - [ ] 组织资料采用响应式两栏/全宽布局，长地址和说明字段不被压缩。
  - [ ] 1366×768 下无需在小编辑框内反复滚动；移动端仍保持可操作。

### P1：产品文案与内部信息清理

#### SET-011 品牌设置作用不明确

- 已确认：当前字段能够保存，但代码中未发现 `displayName/logoUrl/primaryColor` 的实际消费方；现状接近“只存不生效”。
- 修复：
  - [ ] 明确三个字段的产品作用域和生效位置。
  - [ ] 若本轮可交付实际展示，增加即时预览并至少在组织设置/组织身份区域消费。
  - [ ] 若某字段尚未接入，禁止暗示已生效，改为只读“尚未启用”或移除入口。
  - [ ] 保存反馈说明生效位置，刷新后回读。

#### SET-012 移除“权威源/v1”等内部提示

- 用户点名：`Entitlement 权威源 · v1` 及其他 `XXX 权威源`。
- 规则：
  - [ ] 普通页面不显示 authority、entitlement、revision、digest、内部错误码。
  - [ ] 需要表达可信度时使用“已同步”“数据来自平台配置”“最后更新时间”等用户语言。
  - [ ] 版本、签名、基线仅放入显式“高级诊断信息”，默认折叠且仅管理员可见。
  - [ ] 扫描 Badge、空态、错误框、成功回执和预览详情中的同类文案。

## 4. 实施顺序

1. **建立可重复巡检工具**：从两个注册表导出页面 URL；浏览器采集标题边界、按钮、禁用原因、Tab 和错误信息。
2. **修统一底座**：SET-009、SET-010、SET-012，先消除跨页面布局/文案类问题。
3. **修个人设置闭环**：SET-001、SET-006、SET-007、SET-008、SET-002。
4. **修组织管理闭环**：SET-003、SET-004、SET-005、SET-011。
5. **扩散扫描**：按共用 API、共用组件和相同错误码搜索所有调用方并补测试。
6. **逐页浏览器验收**：更新第 3 节状态，保存截图、请求结果和回读证据。
7. **完整门禁**：Web/Server 定向测试、全量测试、typecheck、生产构建、启动包预算和 PR CI。

## 5. 测试与证据要求

- 组件测试：布局契约、Tab URL 同步、disabled reason、中文错误映射、表单尺寸。
- Server 测试：409 冲突语义、依赖影响 resolver、会话恢复缓存失效与列表回读。
- 浏览器测试：使用隔离本地账号 `wangzt-admin` 和隔离数据库；写前记录原值，写后刷新回读，必要时恢复原值。
- 截图：至少保存 1366×768、1920×1080、移动宽度三组关键页面。
- 外部依赖：浏览器 Push、OAuth、真实连接器等无法在本地完成时，必须区分“产品缺陷”和“环境未配置”，不得写成已通过。

## 6. 安全、回滚与范围边界

- 不降低权限、冲突检测、签名预览或依赖影响的 fail-closed 约束。
- 不为通过本地测试伪造 staging/production 身份。
- 不修改或手动触发 Workflow；不部署测试/生产环境，除非用户另行明确授权。
- 每类修复独立提交；出现回归可按提交回滚，不回滚用户无关改动。
- 本文状态是执行清单，不等同于代码完成、部署完成或业务验收完成。
