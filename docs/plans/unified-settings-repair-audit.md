## 1. 目标与完成定义

本轮不是只修用户已报告的单点，而是同时完成以下四件事：

1. 所有设置/管理页面使用同一内容坐标系，页头、标签页、提示条、表单和列表左边界一致。
2. 修复已报告功能故障，并沿相同组件、接口、权限链路排查其他页面的同类问题。
3. 隐藏面向实现者的内部术语、版本号和错误码，改成用户能理解且能采取行动的说明。
4. 对设置注册表和管理页面注册表中的每个页面建立按钮清单，逐项点击、保存并回读。

满足以下条件才能从 Draft 转为 Ready：

- [ ] 本文所有 P0/P1 项完成，代码检查和自动化测试通过。
- [ ] 个人设置 8 页、组织/平台管理 31 个导航入口均完成浏览器逐页验收。
- [ ] 每个可见按钮至少覆盖：可点击、禁用原因、成功反馈、失败反馈、刷新后回读。
- [ ] 有写操作的页面使用隔离测试数据；恢复/保存类操作同时验证 API 回读或列表回读。
- [ ] 1366×768、1920×1080、移动断点上下至少各检查一次布局。
- [ ] 未配置的外部能力显示准确的可操作说明，不以超时或内部错误码冒充用户错误。

## 2. 已确认问题与修复任务

### P0：功能不可用或反馈与事实不一致

#### SET-001 我的 Agent 保存返回 409

- 现象：修改 Agent 名称和签名后显示 `Failed to update agent profile: 409`。
- 已确认：前端只拼接 HTTP 状态，丢失服务端错误正文；保存后也没有用服务端结果刷新本地基线。
- 待确认：409 的直接来源是写入安全栅栏、并发版本还是当前账号/组织状态。
- 修复：
  - [ ] 在本地浏览器和 Network 中复现并记录响应正文。
  - [x] 修正服务端或调用契约，不通过吞掉冲突绕过安全校验。
  - [x] 共用 API 错误解析，向用户展示中文原因和恢复动作。
  - [x] 保存成功后使用响应值更新 profile，刷新页面确认名称与签名仍存在。
  - [ ] 覆盖自助编辑、管理员编辑他人、头像上传/重置的同类错误处理。

#### SET-002 回收站恢复“假成功”

- 现象：恢复提示成功，但会话列表找不到恢复的会话。
- 修复：
  - [ ] 复现并绑定具体 sessionId，记录恢复 API、列表 API 和缓存状态。
  - [x] 检查恢复后列表缓存失效、分页、分组过滤和当前 workspace 投影。
  - [x] 成功提示必须在服务端响应成功且列表刷新完成后出现。
  - [x] 恢复后刷新完整会话列表并直接选中恢复的会话。
  - [x] 同时覆盖恢复失败：保留条目、展示服务端原因并允许重试。

#### SET-003 组织智能体页面按钮不可点击

- 现象：智能体页面顶部操作按钮均无法使用。
- 初步确认：平台管理员代管组织时组件把 `canEdit` 固定为 false，但页面没有明确解释只读原因，表现为按钮失效。
- 修复：
  - [ ] 分别用平台管理员和组织管理员验证权限语义。
  - [x] 有合法代管写权限时允许操作；无权限时显示明确只读原因和正确入口。
  - [ ] 检查刷新、创建、模板创建、编辑、启停、头像上传和保存。
  - [ ] 对所有“disabled 但无原因”的管理按钮做同类扫描。

#### SET-004 连接器范围预览依赖不可用

- 现象：点击“预览范围变更”显示 `DEPENDENCY_IMPACT_AUTHORITY_UNAVAILABLE`。
- 已确认：治理路由在未注入 dependency-impact resolver 或 resolver 失败时返回 503；前端直接暴露内部错误码。
- 修复：
  - [x] 补齐范围预览的通用运行时影响解析回退。
  - [x] 依赖确实不可用时保留 fail-closed，但展示中文原因、受影响能力和重试动作。
  - [x] 覆盖技能、连接器、模型、工具、执行环境等复用范围编辑器的页面。
  - [ ] 预览成功后验证基线、影响数量、提交和刷新回读。

#### SET-005 预算与计费标签页无作用

- 现象：页面顶部 Tab 点击后内容不切换。
- 初步定位：外层路由把“预算与计费”固定带入 `usageSection=billing`，内层组件同时维护自己的 usage/billing Tab，存在路由归一化和受控值互相覆盖。
- 修复：
  - [x] 一个页面只保留一层页面级导航，不再嵌套失效 Tab。
  - [x] 预算入口由 URL 参数直接确定并支持刷新回读。
  - [x] 分别验证“用量看板”和“预算与计费”内容，不允许两个入口指向同一固定态。

#### SET-007 个人调试模式不可开启

- 修复：
  - [x] 开启前先检查服务端是否配置 Web Push，并在未配置时禁用开关、说明管理员动作。

  - [ ] 验证开启、刷新保持、移除当前设备和多设备列表。

## 4. 实施顺序

1. **建立可重复巡检工具**：从两个注册表导出页面 URL；浏览器采集标题边界、按钮、禁用原因、Tab 和错误信息。
2. **修统一底座**：SET-009、SET-010、SET-012，先消除跨页面布局/文案类问题。
3. **修个人设置闭环**：SET-001、SET-006、SET-007、SET-008、SET-002。
4. **修组织管理闭环**：SET-003、SET-004、SET-005、SET-011。
5. **扩散扫描**：按共用 API、共用组件和相同错误码搜索所有调用方并补测试。
6. **逐页浏览器验收**：更新第 3 节状态，保存截图、请求结果和回读证据。
7. **完整门禁**：Web/Server 定向测试、全量测试、typecheck、生产构建、启动包预算和 PR CI。

## 5. 测试与证据要求

- 组件测试：布局契约、Tab URL 同步、disabled reason、中文错误映射、表单尺寸。
- Server 测试：409 冲突语义、依赖影响 resolver、会话恢复缓存失效与列表回读。
- 浏览器测试：使用隔离本地账号 `wangzt-admin` 和隔离数据库；写前记录原值，写后刷新回读，必要时恢复原值。
- 截图：至少保存 1366×768、1920×1080、移动宽度三组关键页面。
- 外部依赖：浏览器 Push、OAuth、真实连接器等无法在本地完成时，必须区分“产品缺陷”和“环境未配置”，不得写成已通过。

## 6. 安全、回滚与范围边界

- 不降低权限、冲突检测、签名预览或依赖影响的 fail-closed 约束。
- 不为通过本地测试伪造 staging/production 身份。
- 不修改或手动触发 Workflow；不部署测试/生产环境，除非用户另行明确授权。
- 每类修复独立提交；出现回归可按提交回滚，不回滚用户无关改动。
- 本文状态是执行清单，不等同于代码完成、部署完成或业务验收完成。
