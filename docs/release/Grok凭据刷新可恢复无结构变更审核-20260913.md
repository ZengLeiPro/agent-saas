# Grok 凭据刷新可恢复无结构变更审核

## 审核范围

- 基线：`50b222a7a7326f5bcbf50c1343b41d09fc7080fd`（本 PR 相对 `origin/main` 的精确基线）。
- Grok 协议与 OAuth：`server/src/runtime/responses/grokProtocol.ts`、`server/src/runtime/responses/grokOAuthClient.ts`。
- 凭据管理与传输：`server/src/runtime/responses/grokCredentialManager.ts`、`server/src/runtime/responses/grokSubscriptionResponsesTransport.ts`。
- 装配与采集：`server/src/app/modelSubscriptionRuntime.ts`、`server/src/app/runtime.ts`、`server/src/quota/grokQuotaSources.ts`。

## 结论

上述文件均分类为 `no-schema-change`。本批只改变 Grok 订阅凭据刷新失败的判定与恢复策略，没有新增、修改或删除 SQL、DDL、迁移版本、启动建表、数据库后置条件、数据回填或数据删除。`<prefix>_grok_credential_runtime_state`、`<prefix>_grok_credential_refresh_journal` 与 `runtime_provider_quota_snapshots` 的表结构、列与既有读写语句不变。

- `grokProtocol.ts`：OAuth 请求在同一 proxy-required 出站上对连接级失败最多再试两次；新增“授权服务器明确拒绝”（`invalid_grant`、`invalid_token`、`expired_token`、`unauthorized_client`、`invalid_client`）与“刷新瞬态失败”两组错误码及判定函数。协议 URL、可信端点校验与出站包装器不变。文件中的 `GRANT` 只是 OAuth 术语，不是 SQL 语句。
- `grokOAuthClient.ts`：刷新已换出新令牌后 userinfo 不可用时，以同一响应 `id_token` 的 `sub` 与已登录身份做连续性比对，不再丢弃已换出的 grant；发现文档缓存延长到 1 小时。首次登录仍只信任 userinfo。
- `grokCredentialManager.ts`：只有授权服务器明确拒绝才写 `auth_unavailable`；传输/上游/本地写入失败释放 refresh journal 中的 fence、抛 `refresh_transient_failure`，下一次访问沿用同一 refresh token 重试；提前刷新失败但 access token 仍有效时继续使用旧令牌；旧版本留下的 `refresh_outcome_unknown` 标记视为可恢复；提前刷新窗口从 5 分钟改为 10 分钟；刷新失败写脱敏 WARN 日志。对两张 Grok 运行态表只复用既有 `get/markAuthUnavailable/clear/begin` 语句。
- `grokSubscriptionResponsesTransport.ts`：请求前绑定查询遇到瞬态刷新失败时跳过该账号，不标记、不换号。
- `modelSubscriptionRuntime.ts` / `runtime.ts`：仅把 `serverLogger.child('GrokSubscription')` 注入 Grok 凭据管理器；启动根的迁移、建表与后置条件调用未变。
- `grokQuotaSources.ts`：采集阻断判定改为只对明确拒绝停采，瞬态失败继续采集以触发恢复；快照写入路径不变。

本批没有 `DROP`、`TRUNCATE`、列改名、类型收窄、约束收紧或历史数据重写；不需要 contract 或 expand 发布。

## 现场依据

- 生产 Vault 中 4 个 Grok 凭据全部停在 generation 1，三次「凭据丢失」分别发生在各自 access token 到期前 5 分钟的首次刷新（09-13 00:28、04:38、16:49），运行态表留下 `refresh_outcome_unknown` 与未清理的 refresh journal。
- 前两次由旧 Runtime Worker 出口配置缺 `auth.x.ai` 触发，第三次由共享代理连接级失败触发；ECS 经 `172.16.177.77:7890` 对 `auth.x.ai` 与 `cli-chat-proxy.grok.com` 各探测 24 次，均 3 次连接失败（12.5%）。
- 同一账号在 Mac Mini CLIProxyAPI 上按 6 小时周期刷新持续成功，说明 grant 本身有效。

## 验证证据

- `server/src/__tests__/grokCredentialLifecycle.test.ts`：瞬态失败不标永久失效、fence 释放后同一 token 重试、明确拒绝才 `auth_unavailable`、有效期内沿用旧令牌、旧标记自动恢复。
- `server/src/__tests__/grokOAuthContracts.test.ts`：连接级失败同代理重试、userinfo 不可用时 id_token 身份连续性、明确 `invalid_grant` 不重试。
- `server/src/quota/grokQuotaSources.test.ts`：只对明确拒绝停采。
