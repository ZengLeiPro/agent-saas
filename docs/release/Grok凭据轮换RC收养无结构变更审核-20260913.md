## 结论

上述文件均分类为 `no-schema-change`。本批只允许代码发布后、配置 digest 未变时，把已签名快照的 `releaseId` 收养到当前 RC，并回写活动色 release env 的凭据版本；没有新增、修改或删除 SQL、DDL、迁移版本、启动建表、数据库后置条件、数据回填或数据删除。Grok / Codex 运行态表、Vault 结构与既有读写语句不变。

- `productionModelPublisher.ts`：凭据轮换在 `phase === committed` 且配置 digest 与磁盘/expected 一致时，允许 `state.releaseId !== 当前 RC`；只推进 `credentialVersionDigest` 并改写 publication 的 `releaseId`。配置内容变了、未 committed、磁盘有未发布变更，仍拒绝。
- `productionModelPublication.ts`：轮换成功后把 `credentialVersionDigest` 写回当前活动色 `*.release.env`；digest 不一致则失败。不触及数据库。
- `write-production-identity.mjs`：digest 未变时绑定 API/Worker 现场 observed 凭据版本，并回写对应 release env。两边版本不一致则失败。
- `grokProductionPublication.test.ts`：新增「旧 RC 签名快照上轮换后 publication 变成当前 RC」用例；原 T20–T22 路径保留。该文件是既有历史审核的验证证据，字节变化必须重绑 digest。

本批没有 `DROP`、`TRUNCATE`、列改名、类型收窄、约束收紧或历史数据重写；不需要 contract 或 expand 发布。
