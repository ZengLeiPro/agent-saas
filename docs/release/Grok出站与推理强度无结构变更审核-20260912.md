# Grok 出站与推理强度无结构变更审核

## 审核范围

- 基线：`config/release-migration-reviews.json` 中登记的全部历史生产基线。
- 运行时装配：`server/src/app/runtimeGovernanceConnectors.ts`、`server/src/app/runtimeEgressAssembly.ts`。
- 出站配置与分派：`server/src/data/egressConfig.ts`、`server/src/runtime/egressDispatcher.ts`、`server/src/runtime/egressRequestPolicy.ts`。
- Grok 协议：`server/src/runtime/responses/grokProtocol.ts`。

## 结论

上述六个文件均分类为 `no-schema-change`。本批只调整进程内和共享文件中的出站配置刷新、代理凭据刷新、HTTP/WebSocket 路由前刷新，以及 Grok 请求的代理必选和禁止直连降级标记；没有新增、修改或删除 SQL、DDL、迁移版本、启动建表、数据库后置条件、数据回填或数据删除。

`runtimeEgressAssembly.ts` 是从既有 `runtimeGovernanceConnectors.ts` 提取的运行时装配模块。它创建 `EgressConfigStore`、读取 SecretVault 中的代理凭据并构造出站分派器，不连接数据库，也不改变任何 Store 的初始化顺序。旧文件中被删除的内容完整迁入新模块，删除的是 TypeScript 装配代码，不是数据库结构或数据。

`egressConfig.ts` 继续使用既有 JSON 文件，只增加内容摘要和有界轮询，以便长期运行的 API/Worker 在请求前看见其他进程原子写入的新版本。`egressDispatcher.ts` 和 `egressRequestPolicy.ts` 只增加本地 Symbol 请求策略及 fail-closed 分支：Grok 被标记为代理必选后，域名未命中、代理不可用或代理请求失败都直接报错，不再尝试 direct。`grokProtocol.ts` 仅把既有单次请求包装器换为代理必选的单次请求包装器。

本批推理强度支持位于 Grok 请求规范化与 transport 请求体生成路径，不改变数据库字段或持久化形状。`grok-4.6` 接受 `low`、`medium`、`high`、`xhigh`；`grok-4.5` 系列接受 `low`、`medium`、`high`；目录显式声明 `supportsReasoningEffort: false` 时仍拒绝，未知模型仍按不支持处理。通过校验的值保留为 Responses API 的 `reasoning.effort`，不会只在界面保存后被运行时丢弃。

## 验证证据

- `server/src/__tests__/egressConfigAdmin.test.ts`：验证另一个 Store 实例写入后，长期运行实例可读取新版本。
- `server/src/__tests__/runtimeEgressAssembly.test.ts`：验证真实运行时装配在 Grok 路由前刷新共享配置与代理凭据。
- `server/src/__tests__/egressDispatcher.test.ts`：验证请求前刷新，以及代理必选请求在未命中或代理失败时都不会直连。
- `server/src/__tests__/grokTransportContracts.test.ts`、`grokModelCatalog.test.ts`、`grokOAuthContracts.test.ts`、`grokSubscriptionQuota.test.ts`：验证 Grok 推理参数进入真实请求体，所有模型、OAuth、额度和 Responses 路径均携带代理必选标记。
