# Grok 套餐采集无结构变更审核

## 审核范围

- 基线：`5cc153f4c8cc1603b0cb4bf1ec8020d3d6249cca`（本 PR 相对 `origin/main` 的精确基线）。
- Grok 协议：`server/src/runtime/responses/grokProtocol.ts`。
- 套餐采集：`server/src/quota/grokSubscriptionQuota.ts`、`server/src/quota/grokQuotaSources.ts`、`server/src/quota/providerQuotaService.ts`。

## 结论

上述文件均分类为 `no-schema-change`。本批只调整 Grok 套餐额度采集的错误传播、凭据失效时跳过取数，以及同一代理上的有限重试；没有新增、修改或删除 SQL、DDL、迁移版本、启动建表、数据库后置条件、数据回填或数据删除。快照仍写入既有 `runtime_provider_quota_snapshots`，表结构与列不变。

- `grokProtocol.ts` 仅让 `GrokProtocolError` 接受可选 `ErrorOptions`，以便保留传输层 `cause`；协议 URL、校验和请求包装器不变。
- `grokSubscriptionQuota.ts` 在既有 `proxyRequiredSingleAttemptEgressFetch` 上对传输错误或 5xx/429 再打同一代理一次，不打开失败直连。
- `grokQuotaSources.ts` 在 `auth_unavailable` / `refresh_outcome_unknown` 时省略 `collect`，并把失败文案带上脱敏后的传输原因。
- `providerQuotaService.ts` 对 `skipCollect=auth_unavailable` 的点名刷新返回「请先重授权」，周期采集不写新失败快照。

本批没有 `DROP`、`TRUNCATE`、列改名、类型收窄、约束收紧或历史数据重写；不需要 contract 或 expand 发布。

## 验证证据

- `server/src/quota/providerQuotaService.test.ts`：周期采集不打 billing、点名刷新拒绝。
