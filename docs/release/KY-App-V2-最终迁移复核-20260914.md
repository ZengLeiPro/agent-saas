# KY App V2 最终迁移复核（2026-09-14）

## 复核范围

本复核把 WP2 的 V48 expand 迁移审核延伸到 PR #698 的最终叠加结果。复核只覆盖以下已发生字节变化的数据库相关文件，不批准未列出的迁移或运行时 SQL：

- `server/src/data/governance-schema/latestMigrations.ts`
- `server/src/data/governance-schema/migrations.ts`
- `server/src/data/governance-schema/v48KyAppAsymmetricIdentityMigration.ts`
- `server/src/kyapp/enrollment/store.ts`
- `server/src/kyapp/systems/store.ts`
- `server/src/kyapp/workload/deploymentKeyStore.ts`
- `server/src/kyapp/workload/replayStore.ts`

## 组合审核结论

V48 本身仍为 expand-only：只给既有安装表增加 4 列，并新增授权操作、部署公钥和防重放 3 张表及索引、约束；不删除表或列，不重写 V1 数据。迁移序列只是在 V47 后追加 V48，最高版本从 47 单调提升到 48。

WP7 之后 `enrollment/store.ts` 新增授权过期收口和激活 ready 状态写入。本轮未知结果恢复继续在同一张 V48 授权操作表内使用既有 `status`、`last_error_code`、`diagnostic_id`、`result_json` 和 `version` 列：兑换提交后写入 `activating`，激活失败按是否需要人工处理写入 `failed_retryable` 或 `needs_human`，重试查询把这些中间态纳入同一安装实例的最新操作；没有新增或改变 SQL 表、列、索引、约束及数据类型。`deploymentKeyStore.ts` 新增 next/current/previous 公钥轮换事务；`systems/store.ts` 只映射 V48 新列；`replayStore.ts` 仍只读写 V48 防重放表。这些模块均不在启动时创建或改变数据库结构，因此分类为 `no-schema-change`。轮换事务只更新 V48 已审核结构，不扩大迁移范围。

历史审核采用组合复核：只有登记项旧 `targetDigest` 精确等于本次已核对的前态摘要时，才把该路径推进到本复核的最终摘要；同时按每个历史基线逐字节回读上述 7 个文件，只补入相对该基线确有变化但尚未登记的路径，并追加本文证据。未知前态或未列出路径一律不自动更新。原有 `baselineDigest`、分类、理由、其他文件和原证据全部保留。

迁移检测器的生产启动结构根清单补入授权操作、部署公钥和防重放 3 个存储模块，使这些入口继续接受严格审核，没有放宽 SQL 分类或审核规则。V47 回归测试改为按版本号核对 V47，V48 回归测试继续单独确认最新版本为 48，避免把“V47 存在”和“V47 永远是最后一个版本”错误绑定。

## 后置条件与回滚

继续使用 `config/release-migration-postconditions.json` 中与 V48 源码摘要绑定的 `ky-app-v2-asymmetric-identity-schema`：回读 4 个安装身份列、3 张新表、current/next 唯一索引以及敏感字段不存在。真实 PostgreSQL 测试已补充 next 公钥登记、原子切换、previous 接受窗口和撤销，并继续覆盖迁移幂等、授权码和 proof 并发消费以及敏感字段检查。激活与回调测试另外覆盖 token 响应丢失、activation 响应丢失、同一 operation 重试，以及失败状态的可恢复收口；这些验证不替代 V48 的结构后置条件。

应用回滚只关闭 V2 接入开关并保留 V48 结构；不得删除新增表列。V1 安装继续通过默认 `auth_mode=v1_symmetric` 运行。本复核不代表迁移已部署或 Staging 已验收。
