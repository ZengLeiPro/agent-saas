# KY App WP5 交付迁移审核

## 变更

- 治理 schema 版本从 43 追加到 44。
- 新增 `<prefix>_ky_app_onboard_executions`，保存开箱请求摘要、逐步状态、结果和中断位置，用于跨进程恢复及相同安装实例串行执行。
- 新增 `<prefix>_ky_app_delivery_records`，保存交付清单、成员导入结果、首登引导、积分通知去重状态和离场计划状态。
- 两表只新增查询索引；不修改 v1～v43 的表、列、索引或既有迁移语句。

## 兼容性结论

本批是 expand-only。旧版 Server/Worker 不读取两张新表，可以继续运行；新版首次启动创建新表后再启用 WP5 路由与维护循环。迁移没有数据回填、外键扫描、列重写、对象删除或锁住既有大表的操作。

回滚到旧应用版本时两张表保留但无人读取，不需要 contract migration。离场流程只在管理员二次确认后运行，且运行期只停用安装实例、吊销服务凭据；迁移本身不执行任何离场动作。

## 本地验证

- v44 静态契约验证：两张表及索引均为 `CREATE ... IF NOT EXISTS`，不存在 `DROP`、`DELETE`、`ALTER COLUMN` 或回填语句。
- 治理版本清单验证：版本号 43→44 严格追加，旧迁移次序不变。
- WP5 定向单测、Server/Web typecheck、五包测试与构建、Web 全量测试和工程棘轮已通过。
- 本机未配置隔离 `TEST_DATABASE_URL`，PostgreSQL 集成测试按门禁设计跳过；必须由 PR Linux/PostgreSQL CI 运行后才能形成真实 PG 证据。

## 发布约束

- 合并不代表部署。必须走当前 RC/Promotion 发布链，先 expand、再启动新代码。
- 正式激活前必须完成隔离 Staging 的八条交付验收；生产 `kyApp` 配置、受管应用域 DNS/TLS、共享 SecretVault 与真实通知接收人需另行确认。
- 本批没有 contract 阶段；不得为了回滚清理新表。
