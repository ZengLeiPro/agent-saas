# PR672 队列残留收口无结构变更审核

## 审核范围

- 基线：`51f96d2072b3f929de0a8f9a51bc463824cfd852`（PR #672 相对 `origin/main` 的精确基线）。
- 领取资格与恢复查询：`server/src/runtime/runLeaseEligibility.ts`、`server/src/runtime/runStoreQueries.ts`、`server/src/runtime/runStoreRecoveryQueries.ts`、`server/src/runtime/background/backgroundTaskRuntime.ts`。
- 告警与装配：`server/src/runtime/platformIncidentPolicy.ts`、`server/src/app/runtime.ts`。

## 结论

上述文件均分类为 `no-schema-change`。本批只调整既有 `runs` / `steering_inputs` 上的只读领取资格与恢复选择谓词，并把同一段条件复用到队列告警；没有新增、修改或删除表、列、索引、约束、启动建表、数据回填或数据删除。

- `runLeaseEligibility.ts` 是新模块，内容是把 `acquireLease` 里已经存在的队尾、活跃会话和 steering 阻断条件抽成共享 SQL 片段。
- `runStoreQueries.ts` 的 CAS 仍写入同一组列，只把上述片段内联回去。
- `runStoreRecoveryQueries.ts` 把 `metadata->>'subagent' IS DISTINCT FROM 'true'` 收窄为「直接子 Agent」；后台任务协调 Run 继续由调度器恢复。
- `backgroundTaskRuntime.ts` 用 `COALESCE(..., 'false')` 把缺失的 `subagent` 显式视为 false，避免 SQL 三值逻辑把普通 Run 误判成子 Agent。
- `platformIncidentPolicy.ts` 的队列阻塞告警改为复用同一领取资格谓词，不再把不可领取的历史残留算成平台事故。
- `runtime.ts` 只把已经初始化的共享 `PgEventStore` 交给 session 缺失时的终态路径，并转发失败原因。

本批没有 `DROP`、`TRUNCATE`、列改名、类型收窄、约束收紧或历史数据重写；不需要 contract 或 expand 发布。生产上线后由调度器按新谓词自动收口过期后台任务，不需要手改表。

- `server/src/__tests__/platformIncidentPolicy.test.ts`：验证告警与 lease 领取共用同一资格 SQL。
