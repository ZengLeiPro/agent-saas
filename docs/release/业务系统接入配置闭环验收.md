# 业务系统接入配置闭环验收

适用于 Staging 和生产，同一套后端处理逻辑，不使用环境白名单或直接改库绕过权限。Staging 通过不等于生产业务验收通过；生产必须用本环境组织、域名和凭据重新验收。

## 一、发布前检查

1. 确认目标组织、系统 ID、已发布 Manifest digest、业务服务地址和页面地址。已有组织接入不新建组织、不重复开户、不赠送额度。
2. 平台已启用 `kyApp`，治理存储为 PostgreSQL，SecretVault 正常装配；系统目录和组织安装目录均可查询。缺少权威存储时应报服务不可用，不得用空数组假装没有依赖。
3. 对本次候选 SHA 和实际生产基线 SHA 生成迁移计划，所有阻断项为零。已有组织接入依赖 V45 等随版本提供的迁移；不能仅检查新修复是否包含 SQL。本次范围影响预览修复不新增表、不要求手动补数据。
4. 确认组织权益有效且具有 `integrated_system` 范围基线。缺基线应先按受控治理修复流程处理，不直接插入安装或把所有资源范围改成 `all`。

## 二、平台管理员完成配置

1. 在业务系统详情的“接入配置”维护真实 HTTPS 服务地址和页面地址。保存后回读；此处默认值不会追溯覆盖已有安装实例。
2. 读取目标组织现有权益范围，仅将目标系统加入 `integrated_system` 的选定列表，保留其他系统与其他资源类型。若本来是 `all`，无需重复授权。
3. 通过范围预览接口取得签名预览，再提交并回读：
   - `GET /api/governance/access/entitlements?tenantId=<组织ID>`
   - `POST /api/governance/access/entitlement-scopes/integrated_system/preview?tenantId=<组织ID>`
   - `PUT /api/governance/access/entitlement-scopes/integrated_system?tenantId=<组织ID>`
   - 提交携带预览返回的 `previewId`、`baselineDigest`、`expiresAt` 和原变更字段。版本或目录变化须重新预览，不盲目重试旧请求。
4. 回读 `/api/app-contract/v1/systems/<系统ID>/connection-options/<组织ID>`，确认 `eligible=true`，再在“组织接入”选择已有组织和该组织有效联系人，创建或恢复接入。已有安装先回读，不重复创建。
5. 平台管理员可以代领该安装凭据。先准备安全落地位置，再领取一次性凭据；不得写入仓库、截图、工单或日志。生产与 Staging 不复用凭据、安装密钥和安装 ID。

领取接口的 `installationKey` 使用业务 SDK 可直接接受的 Base64URL 编码。历史版本若返回标准 Base64，须在受控服务器内以 `Buffer.from(value, 'base64').toString('base64url')` 转换，并校验解码后仍为同一份 32 字节密钥；这是编码转换，不是轮换。禁止把密钥粘贴进命令参数或打印转换结果。

范围影响预览列出目标组织所有未删除安装的 ID 与状态版本，属于保守的受影响清单；不是自动停用计划。变更范围只调整安装准入，不删除已有安装或成员分配。要停止已有访问，应执行该安装的停用操作并另行验收。

## 三、业务服务器配置及业务验收

1. 对准业务系统对应环境的服务器，由已授权运维人员把凭据和安装信息写入该服务专用的受限环境文件或密钥管理服务，加载配置并重启该业务服务，不重启其他应用。
2. 业务系统按合同完成凭据确认；配置平台实际返回的域名验证记录，执行域名验证。核对 ready 上报、Manifest digest 与登记版本一致。

   拆分部署必须由 headless `runtime-worker` 启动业务系统后台任务。候选和排空进程不得执行后台任务；已验证域名的 pending 安装允许先取得 ready，再继续接入启用，不需要人工先启用来触发探测。事件投递仍仅针对 enabled 安装。

3. 确认安装达到可用状态，为测试成员分配安装访问权；验证 Agent 中打开真实业务页面、执行一项只读能力、查看诊断结果。平台健康检查 200 不能替代这些步骤。
4. 对采用“独立运行 + 可选 Agent 接入”的业务系统，还要分别验收：未配置 Agent 凭据时独立登录与业务页面可用；启用接入后 Agent 鉴权正常。历史演示服务若尚未实现独立模式，不得因平台修复完成而标记该项通过。

验收证据至少保留：环境、前后端 SHA、系统/组织/安装 ID、范围保存前后版本、`eligible` 结果、凭据确认状态（不含凭据）、域名/ready/诊断结果和真实页面截图。任一外部配置未完成，应标记“平台通路通过，业务接入未闭环”。

## 四、自动回归与故障恢复

`server/src/__tests__/governanceIntegratedSystemScopeRuntime.test.ts` 使用真实 Express 路由，覆盖平台管理员跨组织操作、组织隔离、普通成员拒绝、首次授权、保存回读与安装准入联动、撤回范围、失效目录和权威查询失败。该文件纳入现有服务端测试，无需新建发布 Workflow。

同时执行已有组织接入 PostgreSQL 测试、凭据确认测试、服务端类型检查和构建。生产发布后仍须按第二、三节在真实目标环境验收，不能凭 CI 绿色直接宣布业务接入成功。

范围配置回退：重新读取最新版本，通过预览/提交恢复原选定列表，保留无关配置；这不会自动删除安装或撤销已领取凭据。应用版本回滚按既有发布流程执行，凭据泄露或需要轮换须单独授权处理。
