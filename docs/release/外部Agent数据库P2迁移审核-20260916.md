# 外部 Agent 客户数据库 P2 迁移审核

- 日期：2026-09-16
- 阶段：P2 客户数据库只读查询
- 结论：`expand`，可先于业务流量发布，不修改或回填任何既有表。

## 结构变更

`PgDatabaseConnectionStore.init()` 在 PostgreSQL advisory lock 内幂等创建两张新表：

- `<prefix>_external_database_connections`：保存租户绑定、非敏感连接元数据、SecretVault 引用、schema/table 白名单、脱敏列和生命周期状态。
- `<prefix>_external_database_query_audit`：保存连接、API Client、conversation/session/run 身份、SQL SHA-256、结果规模、耗时和受控错误码。

两张表均为新增。查询审计表仅外键引用本批连接表，不修改 P0/P1 表，不启动回填。数据库密码、网关 token、完整 SQL 和查询结果均不进入数据库连接元数据或审计表。

## 运行期安全边界

- 密码和 token 只写入 SecretVault；管理 API 响应不返回 `secret_ref` 或明文。
- PostgreSQL 连接测试拒绝 superuser、建库、建角色、复制、绕过 RLS 权限及对允许表的写权限。
- SQL 经 AST 校验，只接受单条 SELECT/只读 CTE；物理表必须带 schema 且同时命中 schema/table 白名单。
- 执行使用 `BEGIN READ ONLY`、statement timeout、`search_path=pg_catalog`、行数/字节数/并发上限和敏感列脱敏。
- Tool 的连接 ID 只从受信任 external session 元数据读取，并在每次调用时重新核对租户、API Client 状态和当前授权。
- 外部 API 会话固定 `memoryAutomationEligible=false`，避免查询结果进入长期记忆自动化。

## 验证证据

- `server/src/__tests__/databaseReadOnlyPolicy.test.ts`：覆盖只读 SELECT/CTE，以及写入、多语句、锁、未限定表、越权表和危险函数拒绝。
- `server/src/__tests__/databaseQueryExecutor.test.ts`：覆盖 SecretVault、网关 token、行数上限和敏感字段脱敏。
- `server/src/__tests__/databaseQueryReadonlyToolProvider.test.ts`：覆盖工具可见性、动态授权复核和仅哈希审计。
- `server/src/__tests__/externalDatabaseConnections.test.ts`：覆盖连接登记不泄密和 API Client 绑定。
- `server/src/__tests__/databaseQueryPostgres.pg.test.ts` 在真实 PostgreSQL 16 上以非特权只读角色验证连接权限、查询、脱敏、写入拒绝和审计持久化。

本地真实数据库命令：

```text
EXTERNAL_DATABASE_TEST_PG_URL=postgresql://postgres:postgres@127.0.0.1:5432/postgres \
  pnpm -F server exec vitest run src/__tests__/databaseQueryPostgres.pg.test.ts
```

结果：3 个真实 PostgreSQL 用例（含发布回读条件）全部通过；P2 单元/API 用例 9 个全部通过。

## 回滚边界

应用代码可以回滚而保留两张新增表；旧版本不会读取或写入它们。删除表、删除审计数据或收窄列约束属于后续独立 contract 迁移，不包含在本阶段。
