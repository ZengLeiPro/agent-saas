# 外部 Agent 运营与组织智能体 P3/P4 迁移审核

- 日期：2026-09-16
- 阶段：P3 运营与计费、P4 组织 Agent 扩展
- 结论：`expand`，两个新增字段均有向后兼容默认值，不要求停机或历史回填。

## 结构变更

- `<prefix>_external_api_clients.allowed_agent_ids TEXT[] NOT NULL DEFAULT '{}'`：保存 API Client 可调用的组织 Agent 白名单。
- `<prefix>_external_conversations.agent_id TEXT NULL`：保存 conversation 创建时固定的可选组织 Agent ID。

初始化继续在 PostgreSQL advisory lock 内执行 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`。既有 API Client 默认白名单为空；既有 conversation 的 `agent_id` 为 `NULL`，因此仍走个人 Agent，不改变 P0-P2 客户行为。

P3 的会话/执行/查询审计读取、费用归因、预算告警、速率和并发门禁不增加新表。费用统计复用现有 Billing usage event 与 ledger，通过外部 execution 的 `run_id` 关联，不复制计费事实。

## 权限与运行时边界

- 创建或更新 Client 白名单时，只接受同租户且已启用的组织 Agent。
- 创建 conversation 时再次核对 Agent 白名单、租户和启用状态；失败统一返回 404，避免跨租户枚举。
- Agent ID 固定在 conversation；消息提交只读取持久化绑定，调用方不能在后续轮次切换。
- 未传 `agent_id` 时保持个人 Agent 路径。
- 运营查询按管理员组织强制过滤；平台管理员必须显式指定组织。
- 查询审计只返回 SQL 摘要、规模、耗时和错误码，不返回 SQL、结果、密码或 token。
- 组织管理员只看到积分与计费收入；内部实际成本只对平台管理员返回。

## 回滚边界

应用代码可以回滚并保留新增列。旧版本忽略这两列，个人 Agent 路径仍可工作。删除列或收窄默认值属于后续独立 contract 迁移，不包含在本阶段。
