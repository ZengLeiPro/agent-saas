## 结论

本批只有 `server/src/runtime/runStoreSchema.ts` 属于 `expand`：在既有运行记录表上增加一个普通、可重复执行的部分索引，用于按 `tenant_id + parentSessionId + subagentAgentId` 查询稳定逻辑子 Agent。索引不唯一，不改变数据行、约束、列、外键或旧写入语义；旧 API/Worker 不依赖该索引，新旧版本可并行运行。

其余受审文件均为 `no-schema-change`：

- 模型配置只增加可选的推理强度能力元数据及 Zod 校验，不执行 SQL 或启动回填；旧配置不提供该字段时保持原行为。
- Runtime 装配只把租户脱敏模型目录 getter 注入 Agent provider；后台运行契约和 RunStore 类型只增加内存参数/返回类型，不执行 SQL。
- Explore Profile 新增不可变 v3，v1/v2 字节与摘要冻结；Profile 和 Worker 的 `default` 策略只扩展运行时配置枚举，不改 Profile 持久化表结构。
- RunStore 拆分出的查询和写入模块只使用既有 `runs.metadata JSONB`、steering 表及运行记录列；稳定 `agent_id`、续接协议和待投递消息均存入已有 metadata，没有新增列或数据回填。
- foreground、background 与 WorkOrder 的续接只追加新 run、steering 输入和 metadata，不重放旧工具副作用，不修改历史终态。

本批没有 `DROP`、`TRUNCATE`、列改名、类型收窄、约束收紧或历史数据重写；不需要 contract 发布。发布阶段仍须按现有 expand 流程执行启动初始化并完成独立回读，不能因 `CREATE INDEX IF NOT EXISTS` 可重复执行而跳过结构证据。

## 数据库后置条件

发布后以 `runtimeEventStore` 的实际 `$tablePrefix` 回读：

- `${tablePrefix}_runs_subagent_identity_idx` 存在，且 `indisvalid=true`、`indisready=true`、`indisunique=false`；
- 索引对象指向 `${tablePrefix}_runs`；
- 索引键依次为 `tenant_id`、`metadata->>'parentSessionId'`、`metadata->>'subagentAgentId'`、`requested_at DESC`；
- 部分条件同时限制 `metadata->>'subagent'='true'` 且包含 `subagentAgentId`。

该只读 SQL 绑定在 `config/release-migration-postconditions.json`。源码摘要、基线摘要和本文摘要绑定在 `config/release-migration-reviews.json`；任一受审文件或证据发生字节变化都必须重新审核。
