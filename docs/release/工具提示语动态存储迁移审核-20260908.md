# 工具提示语动态存储迁移审核

工具提示语保存和清除改为写入独立 PostgreSQL 运行数据。发布绑定的 `config.json`、工具启用状态和 ConfigIdentity 保持原有治理方式。

## 结构与兼容性

- `server/src/data/toolDescriptionStore.ts` 新增 `${tablePrefix}_tool_descriptions` 和 `${tablePrefix}_tool_description_audit` 两张表，分类为 `expand`。
- `server/src/app/runtime.ts` 在启动期间装配并初始化该存储，包含新增建表调用，分类为 `expand`。
- 建表和单行初始化在事务及 advisory lock 内执行；重复启动不覆盖已有数据。无删除旧表、改列、回填或修改既有配置文件。
- 旧配置的提示语按需作为基线读取，不做数据迁移。动态覆盖中缺少键表示继承基线，`null` 表示显式恢复工具原始描述，防止重启后旧覆盖重新出现。
- 新版 API 与 Worker 使用相同数据库和表前缀，Worker 每次开始执行及恢复执行时读取最新覆盖。数据库读取失败时拒绝开始该次执行，避免使用已清除的陈旧提示语。
- 回退到旧代码时，新表可保留且不会影响旧代码启动；旧代码不读取动态覆盖，会使用发布配置中的基线提示语。重新发布新版后恢复读取动态数据。
- 未配置 PostgreSQL 的本地部署保留原文件保存路径。

## 一致性与验证

- 提示语使用独立版本号进行并发校验，更新和审计记录在同一数据库事务内提交。工具开关和运行参数不能混入提示语单独保存请求。
- 生产接口回归覆盖保存、清除、继承基线、保持配置文件不变、并发冲突、描述契约校验和原有生产配置限制。
- 真实 PostgreSQL 回归覆盖并发初始化、两个独立连接的可见性、并发写入只允许一个版本胜出、重启读取及审计失败回滚。
- 页面回归覆盖独立版本提交、清除按钮、清空文本保存、失败保留草稿及保存状态重置。
