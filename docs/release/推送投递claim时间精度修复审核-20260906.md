# 2026-09-06 推送投递 claim 时间精度修复审核

PR：`fix/push-claim-precision-20260906`。审核对象为发布迁移分类器闭包内本 PR 改动的两个启动建表根文件；两者的 `init` 语句逐字未变，改动只在运行期 `claimDelivery` 的 `SELECT … FOR UPDATE` 条件。

## 缺陷

`updated_at` 在 PostgreSQL 是微秒精度，`pg` 驱动把 timestamptz 转成 JS `Date` 后只剩毫秒；`claimDelivery` 用列表快照的 `updatedAt` 做 `updated_at=$5::timestamptz` 等值比较，除非微秒恰好为 0 否则永远不等，于是每次投递都被判成「记录已变更」返回 null 并计入 skipped。真实 PG 复现：`pgUpdatedAt=…57.429185+00`、`jsUpdatedAt=…57.429Z`、claim=null（Web Push 与 APNs 两个 store 同样结果）。这意味着生产 Web Push 自上线以来通过该路径的投递实际全部 skipped；APNs 抄了同款。

## 逐文件结论

| 文件                          | 分类                       | 审核依据                                                                                                                                                                                                   |

| `server/src/webPush/store.ts` | no-schema-change           | `init` 的 `CREATE TABLE/INDEX IF NOT EXISTS` 逐字未变；只改 `claimDelivery` 的 `WHERE` 为 `date_trunc('milliseconds', updated_at)=date_trunc('milliseconds', $5::timestamptz)`，并补注释。无 DDL、无回填。 |
