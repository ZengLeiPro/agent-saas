# 生产配置漂移修复无结构变更审核

## 审核结论

`server/src/app/runtime.ts` 本批分类为 `no-schema-change`。改动只涉及模型辅助引用的启动校验、共享配置事务装配，以及将 memory polling 的运行态刷新并入统一事务；没有新增或修改 SQL、DDL、启动建表、迁移调用、数据回填或数据删除。

## 逐项核对

- 启动时调用 `assertAuxiliaryModelRefsResolvable`，只读取并校验已经解析的模型配置。
- 模型热更新装配新增 guardrail 运行态快照读取器，供同一进程内事务回滚，不接触数据库。
- memory polling 不再独立读取磁盘并局部覆盖 `AppConfig`，改由 `SharedConfigRefresher` 的 prepare/commit/rollback 路径更新内存对象。
- leader 获得后及每 5 秒的轮询改为调用统一共享配置刷新器；停止时清理对应定时器。
- 记忆轮询的数据库查询、调度账本、会话事件、治理 migration 及全部 store 初始化代码均未修改。

## 验证

- Server typecheck 与 build 通过。
- 配置热更新、跨进程悬空引用修复、memory polling 事务和发布 ConfigIdentity 定向回归通过。
- 工程棘轮通过，`runtime.ts` 行数由 3004 收紧为 2989。
- CI 的 PostgreSQL、Server 四分片、Web、Shared、Mobile 和构建任务均通过；本记录仅补足静态迁移审核门禁要求的源码哈希绑定。
