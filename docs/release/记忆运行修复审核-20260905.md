# 记忆运行修复审核

## 变更

- L3 默认轮数、配置校验、管理界面上限为 1000；发布 memory_poll v3，v1/v2 配置保持不变，已绑定会话继续使用原版本。
- L2 原子提交及恢复写入使用固定 workspace root 的 UID/GID；保留原文件 mode，新文件 600、新目录 700。通过文件描述符操作，保留符号链接和并发内容校验。
- 领取前对账已终止运行引用：相同租户、会话及用户，且无有效运行租约、无 running 工具。orphaned 的外部动作结果未知时仍保留阻断。仅从真实事件恢复目标水位，不合成 run_finished 或业务成功。
- 对账不修改正在领取或执行的 state；使用同一领取事务与 SKIP LOCKED，每批最多 100 行。已被处理水位覆盖的 started 标记为 permanent_failed/superseded，prepared 或含 commitJournal 的记录留给原恢复流程。
- 缺失 projection 超过一小时或已软删除的会话退役；宽限期内仍重试。文件提交、恢复和回滚后请求刷新该 workspace 的检索索引。
- Edit 模型可见输入只保留 edits 数组；旧单条输入在准备阶段转换，重复、重叠、空目标和多处匹配仍拒绝。L2 草稿使用相同编辑语义。
- ACS 对通用 Invalid 回读 UID/resourceVersion，仅证实并发版本变更才有限重试；同名重建和真正无效 patch 均拒绝。

## 数据库兼容性

本批没有 DDL、启动回填、删除表或修改列。consolidation/store.ts 的 init 原样保留；reconcile.ts 中 UPDATE 仅在运行期 claimDue 事务内执行，更新既有调度列和既有 ledger 状态。没有修改业务运行终态、历史事件、用户记忆正文或 tombstone。

本批涉及的其余启动闭包文件仅为配置、Profile 静态定义和函数装配。哈希审核按 PR base SHA 绑定，分类为 no-schema-change。旧版本可以读取相同表结构。

静态门禁会复核清单中保留的全部发布基线，因此同时延续这些基线的配置目标哈希，并补充本批新增的记忆调度模块审核。最早保留基线至本批 PR 基线之间的 consolidation/store.ts 和 agentProfiles/builtins.ts 内容完全相同；现有其他文件审核及 expand 分类保持原样，没有删除历史基线或调整门禁。

## 验证

- 真实 PostgreSQL：终态缺边界恢复、恢复最后事件水位、仍在运行成员阻断、租约保护、跨租户隔离、未知外部结果保留、ledger superseded 与 prepared journal 保留；原持久层合同一并通过。
- Linux：L2 草稿、恢复、冲突、tombstone、真实 RawAgentLoop 的多轮工具和 Profile 接力回归。root 提交后 uid 501/gid 20 实际读取并追加新文件、嵌套目录和原有 600 文件通过。
- 管理 API 接受并持久化 1000 轮，Web 管理界面保存 1000 轮通过；Server/ACS typecheck、Web build 和工程棘轮通过。
- ACS 通用 Invalid 竞争重试、同版本无效请求不重试、同名重建拒绝及原租约合同通过。

## 发布后操作

代码合并不代表部署。需要发布 App/Worker 与 ACS；外置生产 memory.polling.maxTurns 从既有显式值改为 1000，核对新任务实际绑定 v3。不要修改旧会话绑定或历史配置摘要。

存量 root 属主文件须先逐项核对路径、inode、内容哈希、mode 和 workspace 用户，保存备份后按清单更正属主，保持正文与 mode 不变；不得全盘 chmod/chown。确认 uid 501 可读后刷新相关索引，并独立比较磁盘哈希与索引哈希。最后用真实业务会话验收 L1、L2 提交、L3 整理和新会话检索链路。
