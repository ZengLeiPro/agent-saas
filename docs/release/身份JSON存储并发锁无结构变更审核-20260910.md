## 结论

本次变更分类为 `no-schema-change`。目标文件仍只读写 `users.json`，没有新增、删除或修改数据库表、列、索引、约束、数据库函数或数据回填，也没有执行 SQL。

运行时装配在 PostgreSQL 模式下将已有的 advisory lock 回调注入 UserStore；UserStore 本身不导入数据库驱动、不持有连接，也不执行 DDL/DML。锁只包围 `reload → validate → mutate → atomic rename`，用于防止多个 API/Worker 进程以旧 JSON 快照覆盖彼此结果。本地与测试环境使用同路径的 create-only 文件锁，持久化格式仍为版本 1 的 `UsersFileData`。

## 核对项

- 原有 tenantId、debugMode 和 photoSync 兼容迁移逻辑保持原数据语义，由受锁 mutation 持久化。
- 用户名、手机号和最后有效管理员校验移动到锁内最新快照上执行。
- 写入仍先生成独立临时文件，再以 rename 原子发布；读取损坏或不可读时拒绝写回。
- 源码中没有 SQL 字面量、动态 SQL、数据库迁移入口或生产启动建表逻辑。
- 不需要 `release-migration: expand`、数据库 postconditions 或独立 contract release。
