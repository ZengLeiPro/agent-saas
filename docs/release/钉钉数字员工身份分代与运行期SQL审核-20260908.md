# 钉钉数字员工身份分代与运行期 SQL 审核

本批变更修复钉钉数字员工的消息恢复、账号换绑和群绑定身份分代。审核范围只覆盖本分支实际改动；不代表已执行生产迁移、真实钉钉联调或发布验收。

## 结构变更

- V46 为组织群 binding 增加可空的 `retired_at` 与 `logical_conversation_id`。旧行不回填、不改写，旧版读取和写入仍可使用原列。
- 保留原有 `(account_id, conversation_id)` 唯一约束，因此升级后旧版 `INSERT ... ON CONFLICT(account_id,conversation_id)` 仍有可推断的唯一约束。
- V46 只增加上述可空列及身份分代查询索引，不删除或替换约束，不执行动态 SQL，也不回填存量数据，属于可独立回退应用代码的 expand。
- 把 delivery 复合外键替换为 `ON UPDATE CASCADE` 会删除并重建存量合同，明确不属于 V46，也不随本 PR 的常规 RC 发布。它必须作为独立 contract release 执行，并单独记录锁等待、校验、回滚与数据库读回。
- 新版代码只有在数据库确认 delivery 外键已经有效启用 `ON UPDATE CASCADE` 后，才会归档旧 binding 并创建新 generation；前置合同缺失时抛出 `ORG_AGENT_BINDING_GENERATION_CONTRACT_REQUIRED`，事务整体回滚，不会留下半归档身份。

## 运行期 SQL 变更

- `agentDwsMessages/store.ts` 与 `orgGroupAgents/deliveryClaims.ts` 的差异是 inbox/outbox 状态协调、原正文与原幂等键恢复，以及终态投递预算；没有新增启动 DDL 或回填。
- `orgGroupAgents/store.ts` 仅把 binding 查询委托给身份分代模块，并调整运行期消息恢复调用；建表仍由治理迁移执行。
- `agentDwsAccounts/store.ts` 复用既有 `event_policy_json` 保存一次性换绑意图，复用既有 `identity_updated_at` 作为单调身份 epoch；没有新增账号表列、启动 DDL 或回填。
- `bindingIdentityStore.ts` 的 UPDATE/INSERT 仅在明确换绑后的当前账号身份与 CAS 证据一致、且独立外键合同已完成后执行。旧 binding 只归档不覆盖，合同缺失或创建失败均由事务整体回滚。

## 验证与发布边界

- PostgreSQL 回归覆盖 unknown 投递原子核对、账号换绑 CAS、身份 epoch、独立合同缺失时原子拒绝，以及测试库显式安装该合同后旧 binding 保留、新 binding 生成和旧 WorkOrder/记忆隔离。
- 迁移单测固定 V46 顺序、保留旧唯一约束、禁止删约束/动态 SQL，并确认治理版本连续性；server 类型检查和相关路由/Worker 回归作为应用层证据。
- 后续 contract release 必须在独立变更中完成 delivery 外键替换；本 PR 合并和 V46 expand 成功都不表示该合同已经执行，也不表示账号换绑的 binding generation 已可用。
- 发布前仍须在与生产同主版本的 PostgreSQL 升级测试库执行完整 release migration upgrade，并记录锁等待、迁移耗时、外键校验结果和应用读回。当前分支没有执行部署或生产数据库变更。
- 真实钉钉 OAuth、群消息与私聊投递未在本地伪造为通过；需在获得真实外发和发布授权后单独验收。
