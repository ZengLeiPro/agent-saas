# KY Agent 业务系统及系统能力可配置接入方案

> 版本：v1.1
>
> 状态：方案设计（已补充个人身份与数据权限链路）
>
> 范围：业务系统页面接入、系统能力接入、组织配置、Agent 运行时调用
>
> 原则：基础页面接入不要求改造业务系统；系统已有 API、OpenAPI 或 MCP 时，可通过配置接入 Agent

---

## 1. 建设目标

KY Agent 增加“业务系统”工作区，平台管理员或组织管理员可以按需配置业务系统，并控制：

- 哪些组织可以使用该系统。
- 哪些成员、部门或组织 Agent 可以使用。
- 系统在 KY Agent 中如何展示。
- 系统具有哪些可供 Agent 调用的能力。
- 每项能力使用什么凭据、风险等级和审批策略。
- 能力是否默认启用、绑定给哪些 Agent。
- 系统和能力是否可用、失败原因是什么。

系统接入拆成两个相互独立的部分：

```text
系统页面接入：解决“用户在哪里使用系统”
系统能力接入：解决“Agent 如何查询或操作系统”
```

其中“能力接入”还必须明确身份级别：

```text
组织身份：所有被授权成员共用组织服务账号
个人身份：每个成员连接自己的业务系统账号
```

需要继承业务系统个人权限和数据权限时，必须使用个人身份。组织共享凭据只能证明请求来自某个组织，不能代替个人数据权限。

一个系统可以是：

- 只有页面，没有 Agent 能力。
- 只有 Agent 能力，没有页面。
- 同时有页面和 Agent 能力。
- 页面先接入，能力以后逐步补充。

## 2. 核心设计原则

### 2.1 不强制改造业务系统

页面接入只需要配置已有地址：

```text
系统名称 + 图标 + URL + 打开方式 + 可见范围
```

如果目标系统允许 iframe，则在 KY Agent 右侧展示；如果浏览器不允许 iframe，则降级为新窗口打开。

业务系统继续使用自己的：

- 用户登录
- Cookie 和会话
- 权限控制
- 数据权限
- 页面导航
- 安全策略

KY Agent 不要求业务系统使用 KY Agent 账号体系，也不判断业务系统自身是否允许匿名访问。

### 2.2 能力接入优先使用已有机器接口

系统已有以下任意一种能力即可配置接入：

- MCP Server
- OpenAPI 文档
- REST API
- 标准 HTTP 接口
- 已有 Connector
- 浏览器页面操作

其中 MCP、OpenAPI、REST API 最稳定。

如果系统只有页面、没有任何 API，可以使用浏览器自动化作为补充，但不将其作为第一阶段的核心方案。

### 2.3 展示配置和能力配置分离

系统页面打不开，不影响 Agent 调用 API。

系统 API 暂时不可用，也不影响用户打开系统页面。

### 2.4 复用现有治理体系

不另外建设一套成员权限、凭据和 Agent 能力白名单。

复用现有：

- 平台权益
- 组织策略
- 成员/部门/Agent Assignment
- SecretVault
- OAuth Grant
- MCP Server
- Connector Catalog
- Org Agent `serverAllowlist`、`toolAllowlist`
- 运行时高风险操作批准
- 治理审计

### 2.5 Agent 不处理身份和密钥

Agent 模型只选择能力并产生 Schema 允许的业务参数。当前用户身份、凭据选择和鉴权 Header 注入均由服务端完成。

```text
Agent 负责：选择“查询跟进记录”并提供 month
Runtime 负责：从登录态取得 tenantId、userId、agentId
Gateway 负责：取得当前用户凭据并调用固定 API
业务系统负责：按自己的个人权限和数据权限过滤结果
```

禁止让模型提供 `userId`、`tenantId`、Token 或完整 URL，也禁止用组织管理员账号查出全量数据后再由 Agent 过滤。

## 4. 成员端交互设计

### 4.1 左侧双工作区

左侧顶部增加两个标签：

```text
┌──────────────────────────────┐
│ [开沿 Agent]   [业务系统]    │
├──────────────────────────────┤
│                              │
│ 当前工作区对应的内容         │
│                              │
└──────────────────────────────┘
```

“开沿 Agent”保持现有逻辑：

- 新建会话
- 会话列表
- 企业专家
- 运行状态
- 未读和待处理状态

“业务系统”显示：

- 系统搜索
- 系统分组
- 系统列表
- 系统图标和名称
- 收藏系统
- 系统可用状态
- 最近使用

如果用户没有任何可用系统，不显示“业务系统”标签。

### 4.2 系统右侧内容区

用户点击系统后进入：

```text
/apps/:installationId
```

右侧由统一的 `SystemAppHost` 渲染：

- `iframe`：直接内嵌系统。
- `external`：显示系统介绍和“打开系统”按钮。
- `auto`：优先 iframe，失败后提示新窗口打开。
- `native`：未来用于 KY Agent 原生页面。

### 4.3 状态保持

- 从系统切回 Agent 时，聊天状态不能丢失。
- 从 Agent 切回系统时，保留当前系统和访问地址。
- 第一阶段只保持最近一个系统 iframe。
- 后续可使用 LRU 保持最近 2～3 个系统页面，避免大量 iframe 占用内存。
- PC 使用右侧 iframe；移动端根据配置使用 WebView 或外部浏览器。

### 4.4 个人账号连接

组织管理员把系统分配给成员后，如果该系统能力要求个人身份，当前成员的“能力中心 → 连接器”页自动出现一张“组织提供”的连接卡。

```text
组织分配系统
→ 用户看到“待连接”卡片
→ 用户点击“连接”
→ 完成 OAuth 或录入个人 Token
→ 状态变为“已连接”
→ Agent 才能使用要求个人身份的能力
```

“业务系统”工作区用于打开系统页面；“连接器”页用于连接或断开个人账号。一个系统原则上只展示一张账号连接卡，同一授权可供该系统下多个能力共用。

## 5. 系统接入层级

| 层级              | 接入内容                    | 业务系统是否需要改造           |
| ----------------- | --------------------------- | ------------------------------ |
| L1 页面接入       | URL、iframe、新窗口         | 不需要                         |
| L2 REST 能力      | 配置已有 HTTP API           | API 已支持所需鉴权时不需要     |
| L3 OpenAPI 能力   | 导入 OpenAPI 并选择接口     | API 已支持所需鉴权时不需要     |
| L4 MCP 能力       | 配置 MCP Server             | MCP 已支持所需鉴权时不需要     |
| L5 浏览器能力     | Agent 操作已有页面          | 通常不需要，但稳定性较低       |
| L6 页面上下文联动 | 页面主动告诉 Agent 当前单据 | 需要业务系统配合，属于可选增强 |

基础产品覆盖 L1～L4。

L5、L6 不作为系统接入前提。

若 L2～L4 需要继承个人权限，但业务系统既不支持个人 Token/OAuth，也不支持可验证的用户身份代理，则需要改造业务系统后才能安全接入。

## 6. 平台管理员配置

平台管理增加：

```text
平台管理
└─ 资源中心
   └─ 系统目录
```

平台管理员可以：

- 创建系统模板。
- 配置系统名称、图标和介绍。
- 配置推荐 URL 和允许的域名。
- 配置 iframe、新窗口或自动模式。
- 创建系统版本并发布。
- 绑定 Connector、MCP 或 API 能力模板。
- 定义能力风险等级。
- 定义需要的凭据类型。
- 设置组织权益范围。
- 停用、恢复或退役系统。
- 查看各组织安装和使用情况。

平台管理员的完整接入流程为：

```text
1. 新建系统：名称、图标、介绍、页面地址、打开方式
2. 添加能力：选择 REST、OpenAPI 或 MCP，配置可用工具
3. 选择鉴权：无鉴权、组织共享凭据或用户个人授权
4. 配置风险：只读、写入以及是否需要运行时批准
5. 诊断：检查地址、协议、Schema 和鉴权流程
6. 发布：生成不可变系统版本，供组织安装
```

平台管理员配置的是能力元数据和鉴权方案，不手写运行时 `ToolDescriptor`。发布后由 Capability Gateway 自动转换。

平台系统目录支持以下状态：

```text
draft → published → disabled → retired
```

系统版本发布后不可直接修改；修改时生成新版本，组织安装实例可继续固定旧版本。

## 7. 组织管理员配置

组织管理增加：

```text
组织管理
└─ 智能体与资源
   └─ 已接入系统
```

组织管理员支持两种接入方式。

### 7.1 安装平台系统

从平台已发布的系统目录选择并安装。

平台定义系统能力和安全边界，组织负责：

- 是否启用。
- 显示名称和图标覆盖。
- URL 参数或组织环境地址。
- 可见成员和部门。
- 可用 Agent。
- 当鉴权模式为组织共享时，配置组织凭据。
- 当鉴权模式为个人授权时，不代替成员填写个人凭据。
- 启用哪些能力。

### 7.2 添加组织自定义系统

组织管理员直接填写：

- 名称
- 图标
- 系统地址
- 打开方式
- 显示分组
- 排序
- 可见范围

是否允许组织自定义系统，由平台策略控制：

```text
system.custom.allowed = true | false
```

如果组织还要配置 REST、OpenAPI 等能力，则能力访问域名默认必须与系统页面域名一致；跨域调用需要平台额外放行，避免把能力配置变成任意网络请求入口。

### 7.3 系统配置页签

每个系统安装实例包含：

```text
基本信息
展示方式
系统能力
凭据与授权
成员范围
Agent 范围
运行状态
操作记录
```

## 8. 系统能力接入方式

### 8.1 MCP 接入

配置内容：

```yaml
type: mcp
transport: streamable-http
url: https://example.com/mcp
riskLevel: read_only
authMode: user_oauth
enabledTools:
  - search_customer
  - query_order
```

支持：

- `http`
- `streamable-http`
- 必要时支持受控 `stdio`
- 用户级、组织级、平台级凭据
- OAuth
- 工具白名单
- MCP `tools/list` 诊断
- 连接状态和重试状态

现有 MCP 类型已经支持风险等级、Secret Scope、OAuth 和组织归属，可直接复用。[`shared/src/types/mcp.ts`](../shared/src/types/mcp.ts)

### 8.2 OpenAPI 接入

组织或平台提供：

- OpenAPI URL
- OpenAPI JSON/YAML 文件

系统执行：

1. 解析 OpenAPI。
2. 展示接口列表。
3. 管理员勾选允许 Agent 使用的 operation。
4. 自动生成名称、描述、输入 Schema。
5. 管理员确认风险等级和凭据。
6. 发布成 Connector 版本。
7. 组织启用指定能力。

OpenAPI 导入不能直接把全部接口暴露给 Agent，必须人工选择 operation。

### 8.3 手动 REST 接入

适合接口较少、没有 OpenAPI 的系统。

每个能力配置：

- 能力名称
- Agent 可见描述
- HTTP Method
- Base URL
- Path
- Path/Query/Header/Body 映射
- 输入 Schema
- 输出 Schema
- 超时
- 最大响应大小
- 重试策略
- 幂等性
- 风险等级
- 鉴权模式和凭据类型

示例：

```json
{
  "capabilityId": "huaheng.knowledge.search",
  "name": "查询华恒知识库",
  "description": "按自然语言查询华恒产品、件号、应用范围和销售问答知识",
  "executor": {
    "type": "http",
    "method": "POST",
    "baseUrl": "https://fc.kaiyan.net/huaheng-agent/api/v1",
    "path": "/kb/search",
    "timeoutMs": 15000
  },
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {
        "type": "string",
        "description": "要查询的产品、件号或业务问题"
      },
      "limit": {
        "type": "integer",
        "minimum": 1,
        "maximum": 20
      }
    },
    "required": ["query"]
  },
  "riskLevel": "read_only",
  "authBinding": {
    "mode": "user_oauth",
    "providerId": "huaheng-oauth",
    "scopes": ["knowledge.read"]
  }
}
```

华恒系统当前已有以下适合作为能力接入的接口：

- 知识搜索
- 产品画像
- 价格查询
- 自然语言解析

如果这些接口已支持用户 OAuth/Token 并在服务端执行数据权限，则不需要修改华恒页面或 API，只需在 KY Agent 中配置为能力。如果接口只支持统一服务账号，则只适用于组织共享权限；要继承个人数据权限时必须先补充用户鉴权能力。

### 8.4 浏览器操作接入

当系统只有页面，没有 API 时，可配置浏览器能力：

```yaml
type: browser
startUrl: https://erp.example.com/
allowedOrigins:
  - https://erp.example.com
riskLevel: credentialed_external_write
executionTarget: server-remote
```

运行时通过现有 ACS/Remote Hand 浏览器执行。

限制：

- 浏览器运行环境的登录态与成员 iframe 登录态不是同一个会话。
- 页面改版可能导致自动化失效。
- 写操作必须运行时批准。
- 必须限制可访问域名。
- 适合作为补充方案，不作为可靠业务集成的首选。

### 8.5 能力鉴权模式

平台管理员在发布能力时必须选择一种鉴权模式：

| 模式                     | 适用场景                             | 用户是否需要连接             |
| ------------------------ | ------------------------------------ | ---------------------------- |
| `none`                   | 公开的只读接口                       | 否                           |
| `tenant_shared`          | 组织共享服务账号，不区分个人数据权限 | 否，由组织管理员配置         |
| `user_oauth`             | 业务系统支持 OAuth，要求继承个人权限 | 是                           |
| `user_token`             | 业务系统支持个人 API Token           | 是                           |
| `signed_user_delegation` | 业务系统验证 KY Agent 签名的用户身份 | 否，但业务系统必须支持该协议 |

默认优先使用 `user_oauth`。`tenant_shared` 不得标注为“继承个人权限”。`userId` 不能作为模型参数或普通 HTTP 参数直接传递；若使用身份代理，必须使用短时效签名 Token，并由业务系统验证 `issuer`、`audience`、`tenant`、`subject` 和过期时间。

## 9. 统一能力模型

所有来源最终由 Capability Gateway 归一化成 `ToolDescriptor`。它是运行时产物，不是平台管理员填写的表单：

```ts
interface SystemToolDescriptor {
  systemId: string;
  installationId: string;
  capabilityId: string;
  toolName: string;
  displayName: string;
  description: string;
  inputSchema: Record<string, unknown>;
  outputSchema?: Record<string, unknown>;
  riskLevel: 'read_only' | 'workspace_write' | 'external_write' | 'credentialed_external_write';
  executor:
    | { type: 'mcp'; serverId: string; toolName: string }
    | { type: 'http'; actionId: string }
    | { type: 'browser'; profileId: string };
  credentialRequirement?: {
    scope: 'user' | 'tenant' | 'global';
    credentialType: string;
    providerId?: string;
    scopes?: string[];
  };
}
```

工具名称统一加系统前缀，避免冲突：

```text
system.huaheng_knowledge.search
system.huaheng_knowledge.query_price
system.erp.create_purchase_order
```

Agent 不允许动态指定任意 URL。模型只能提供 Schema 允许的业务参数，目标 URL、Method 和凭据均由已发布配置决定。

## 10. 能力与 Agent 的绑定

系统能力支持分配给：

- 个人 Agent
- 指定组织 Agent
- 所有组织 Agent
- 指定成员
- 指定部门
- 全组织成员

组织 Agent 继续使用现有：

```ts
runtime.mcp.serverAllowlist;
runtime.mcp.toolAllowlist;
runtime.mcp.denyServers;
runtime.mcp.denyTools;
```

对应类型已经存在于 [`shared/src/types/orgAgent.ts`](../shared/src/types/orgAgent.ts)。

绑定规则采用：

```text
用户最终可用能力
=
系统已发布
∩ 组织已安装并启用
∩ 组织拥有权益
∩ 成员/部门已分配
∩ 当前 Agent 被允许
∩ 凭据可用
∩ 运行时风险策略允许
```

任何一层拒绝都不能由下一层放宽。

组织管理员可以提高风险等级或要求更严格的批准，但不能把平台定义的高风险能力降为低风险。

## 11. 身份与凭据模型

### 11.1 用户身份来源

用户登录 KY Agent 后，Runtime 从服务端会话中取得可信身份：

```text
tenantId + userId + agentId
```

这些字段不从 Agent 输出、Tool 入参或前端隐藏字段取值。

### 11.2 组织共享凭据

组织管理员配置，组织成员在授权范围内共同使用。适合 AppKey/AppSecret、组织级 API Token 或内部服务账号。

它只能继承该服务账号的权限。如果业务系统需要识别到具体员工，不能使用该模式替代个人授权。

### 11.3 个人账号连接

成员通过 OAuth 或录入个人 Token，建立 KY Agent 用户与业务系统用户的映射：

```text
KY Agent: tenant_001 / user_123
Business System: crm_user_789
Credential: cred_456
```

推荐 OAuth Authorization Code + PKCE。授权回调后，服务端将稳定的外部用户标识和凭据引用绑定到 `tenantId + userId + installationId + providerId`。连接状态包括：

```text
not_connected → connected → expired/revoked
```

未连接、已过期或已撤销时，要求个人身份的能力必须不对 Agent 暴露。

### 11.4 平台基础设施凭据

仅平台运行时使用，组织管理员不能读取。

### 11.5 凭据安全边界

能力配置仅保存 `credentialRef`，敏感值继续进入 SecretVault。不得将 Secret 写入系统 JSON、MCP Settings、URL、前端响应、日志或 Agent Prompt。

个人 OAuth Token 到期时由服务端使用 Refresh Token 刷新；刷新失败则把连接置为 `expired`，引导用户重新授权。

## 15. Agent 运行时流程

```text
1. 用户发送消息
2. Runtime 从服务端会话读取 tenantId、userId 和 agentId
3. 查询用户有效系统安装实例
4. 查询有效能力和 Assignment
5. 应用 Org Agent MCP/Tool allowlist
6. 按能力 authMode 检查组织凭据或当前用户账号连接
7. 把有效 ToolDescriptor 暴露给模型
8. 模型选择工具并提交结构化参数
9. Runtime 再次使用同一服务端身份做授权，忽略模型生成的任何身份字段
10. 根据风险策略请求批准
11. Capability Gateway 从 SecretVault 解析凭据，必要时刷新个人 Token
12. Gateway 把凭据注入固定 Header，调用业务系统
13. 业务系统验证 Token，并按原有个人权限和数据权限返回结果
14. 记录操作人、外部账号、输入/结果摘要、耗时和错误
15. 将结构化结果返回 Agent
```

授权必须在“工具展示”和“工具执行”两个位置分别检查，避免模型通过历史工具名或伪造调用绕过。

业务数据必须在业务系统端完成权限过滤；KY Agent 不应使用高权限账号查出全量数据后再做二次过滤。

## 16. Capability Gateway

新增统一执行层：

```text
server/src/system-integrations/
├─ catalog/
├─ installations/
├─ effective-access/
├─ account-connections/
│  ├─ oauth-flow.ts
│  ├─ token-binding.ts
│  └─ connection-store.ts
├─ capability-gateway/
│  ├─ mcp-executor.ts
│  ├─ http-executor.ts
│  ├─ browser-executor.ts
│  ├─ request-mapper.ts
│  ├─ response-normalizer.ts
│  └─ audit-recorder.ts
└─ routes/
```

Gateway 负责：

- 输入 Schema 校验
- 固定域名和 Path
- 参数映射
- 从服务端会话绑定当前用户，不信任模型传入的身份
- 解析组织共享凭据或当前用户的个人账号连接
- SecretVault 凭据解析
- OAuth Token 刷新和撤销状态处理
- 鉴权 Header 注入
- 超时和取消
- 响应大小限制
- 重试和幂等
- 风险批准
- 敏感字段脱敏
- 审计记录
- 统一错误码

不允许模型直接控制：

- 完整 URL
- Host
- 任意 Header
- 凭据
- HTTP Method
- 重试次数
- 浏览器目标域名
- `tenantId`、`userId` 或外部账号 ID

## 17. 配置生效策略

配置分为原始配置和有效配置。

### 17.1 原始配置

组织管理员看到的系统安装、能力开关和分配策略。

### 17.2 有效配置

服务端针对当前成员和 Agent 计算出的最终结果：

```http
GET /api/systems/mine
```

返回最终有效系统，不让前端自行合并平台、组织、部门和用户配置。

建议优先级：

```text
平台禁用 > 组织停用 > 显式 deny > 显式 allow > 全员默认
```

系统展示配置可以沿用当前“服务端计算有效状态”的做法，但系统能力采用 deny 优先，不能简单复用工作流卡片的显示覆盖逻辑。

对要求个人授权的能力，系统分配只产生“可见且待连接”状态，不等于能力已可调用。只有当前用户的账号连接为 `connected` 且授权 scope 满足要求时，对应工具才进入有效 `ToolDescriptor` 集合。

## 18. 失败处理

| 场景                          | 产品行为                             |
| ----------------------------- | ------------------------------------ |
| iframe 被目标系统拒绝         | 提示并新窗口打开                     |
| 页面地址失效                  | 系统列表显示“暂不可用”               |
| MCP 无法连接                  | 页面仍可打开，能力标记不可用         |
| API 超时                      | Agent 收到可重试错误                 |
| 个人凭据缺失                  | 引导成员完成授权                     |
| OAuth 回调身份或 state 不匹配 | 拒绝绑定并记录安全审计               |
| 个人 Token 过期或被撤销       | 停止暴露相关工具，引导重新连接       |
| 授权 scope 不足               | 仅停用需要该 scope 的能力            |
| 组织凭据失效                  | 提示联系组织管理员                   |
| 写操作未批准                  | 不执行，保留会话状态                 |
| 能力版本升级                  | 组织继续使用已固定版本               |
| 系统被组织停用                | 新页面打开和新工具调用均拒绝         |
| 工具调用中途停用              | 当前调用按快照完成或取消，并记录审计 |

## 21. 验收标准

### 21.1 页面接入验收

- 组织管理员可添加一个仅包含 URL 的系统。
- 授权成员能在左侧看到系统。
- 未授权成员无法通过直接 URL 打开安装实例。
- 系统在右侧 iframe 实际加载。
- iframe 不可用时能新窗口打开。
- 切回 Agent 后原会话状态不丢失。
- PC 和移动端行为符合配置。

### 21.2 能力接入验收

- 组织管理员可配置 MCP 或 REST 能力。
- Agent 只能看到分配给当前用户和当前 Agent 的工具。
- 不同组织使用相同 `capabilityId` 时，凭据和数据不串租户。
- Secret 不进入 Tool Schema、Prompt、日志和 API 响应。
- 只读能力可以完成真实 HTTP/MCP 调用。
- 写能力未经批准不能执行。
- 停用能力后，下一次运行不再暴露对应工具。
- 实际业务调用需要检查目标系统返回和业务结果，不能只以 HTTP 200 作为业务验收。

### 21.3 个人身份与数据权限验收

- 组织管理员分配系统后，成员在连接器页看到“组织提供 · 待连接”卡片。
- 成员完成 OAuth/Token 授权后，卡片变为“已连接”，且不回显 Secret。
- 用户 A 和用户 B 分别连接自己的业务系统账号，同一查询只返回各自权限范围内的数据。
- 未连接、Token 过期或 scope 不足时，Agent 不能调用对应能力。
- 伪造请求参数中的 `userId`、`tenantId` 或外部账号 ID，不得改变服务端身份与凭据选择。
- 业务系统的结果集合通过业务系统原有权限规则计算，不由 Agent 用全量数据二次过滤。
- 撤销用户的系统分配后，下一次运行不再暴露工具，历史连接不得被其他用户复用。

### 21.4 华恒试点验收

- 华恒页面在 KY Agent 右侧真实展示。
- “查询华恒知识库”由 Agent 发起真实 API 请求。
- 华恒 API 能验证当前成员的个人身份，并在服务端返回权限内数据。
- Agent 能返回带来源结构的查询结果。
- 华恒页面和知识能力可以分别启停。
- 只给华恒组织授权，其他组织不可见、不可调用。

## 22. 当前项目适配结论

现有代码已经具备大部分底座：

- Connector Catalog 已有发布、版本和 digest 设计。[`server/src/data/connectorCatalog/types.ts`](../server/src/data/connectorCatalog/types.ts)
- MCP 已有组织归属、OAuth、凭据 Scope、风险等级和诊断。[`shared/src/types/mcp.ts`](../shared/src/types/mcp.ts)
- Org Agent 已有 MCP Server 和 Tool 白名单。[`shared/src/types/orgAgent.ts`](../shared/src/types/orgAgent.ts)
- Assignment 已支持用户、部门组、所有人和 Agent 分配。[`server/src/data/assignments/types.ts`](../server/src/data/assignments/types.ts)
- 治理引擎已有权益、组织策略、Assignment、长期授权和运行时批准链路。[`server/src/governance/access/types.ts`](../server/src/governance/access/types.ts)

本次真正需要新增的是：

1. “业务系统”一等资源模型。
2. 系统页面宿主和左侧双工作区。
3. 系统安装实例与能力绑定关系。
4. REST/OpenAPI 到统一 ToolDescriptor 的 Capability Gateway。
5. 系统鉴权提供方和用户账号连接。
6. 组织分配后在连接器页展示用户授权入口。
7. 系统、成员、Agent、凭据之间的有效配置解析。

基础系统页面接入通常不需要修改业务系统。能力接入是否需要改造，取决于现有 API、OpenAPI 或 MCP 是否支持目标鉴权模式：如果需要继承个人权限，业务系统必须支持个人 OAuth/Token 或可验证的用户身份代理；否则必须先改造业务系统。
