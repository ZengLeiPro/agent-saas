# KY Agent 业务系统接入管理开发实施文档

> 文档状态：可执行开发方案
>
> 基准日期：2026-09-07
>
> 产品依据：[`docs/业务系统接入管理最终产品形态.md`](./业务系统接入管理最终产品形态.md)
>
> 首期目标：完成标准 KY App 从系统登记、版本发布、组织交付、凭据领取、范围授权到运行运营的后台闭环

## 1. 交付目标

本方案把产品目标拆成可按顺序实施、测试、提交和回滚的开发任务。

P0 完成后必须达到以下结果：

1. 平台管理员可以在后台登记、复核、发布和管理业务系统版本。
2. 平台管理员可以在后台创建并继续执行组织交付。
3. 技术联系人可以在登录后一次性领取服务凭据。
4. 组织管理员可以查看本组织业务系统，并配置成员、部门和 Agent 的访问范围。
5. 平台管理员可以从“业务系统运营”查看健康状态、诊断、凭据和审计，不再进入组织“计费”页操作。
6. 普通成员继续通过 `/apps/:installationId/*` 打开有权访问的业务系统，页面主称谓统一为“业务系统”。
7. 管理员完成上述日常操作时不依赖 `ky-app register`、`ky-app onboard` 或 `ky-app rotate-credential`。

## 2. 实施边界

### 2.1 P0 包含

- 标准 KY App 系统目录与版本管理页面。
- Manifest 上传、校验、语义差异、复核、发布、停用和退役。
- 平台交付列表、新建交付、等待外部处理、继续交付和交付结果。
- 技术联系人一次性凭据领取页面。
- 组织已安装、可安装、待处理、已停用列表。
- 安装实例详情、成员/部门/Agent Assignment、启用和停用。
- 运行状态、诊断、凭据元数据、异常信号、用量和审计。
- 凭据重签、版本切换引导和平台离场操作。
- 平台、组织、成员端导航与文案调整。

### 2.2 P0 不包含

- MCP、OpenAPI、REST 的后台 Manifest 生成器。
- 用户个人 OAuth 或个人 Token。
- 浏览器自动化。
- 移动端 WebView。
- 自动操作业务系统自身的部署平台、DNS 控制台或业务数据库。
- 修改 GitHub Actions、启用新 Workflow 或生产部署。

这些能力分别进入 P1、P2、P3。P0 不为未来能力提前增加无法验收的空页面。

### 3.3 必须补齐的服务端缺口

1. 没有按平台/组织查询安装实例列表的管理接口。
2. 没有系统详情聚合接口；系统列表也没有安装数、风险和异常汇总。
3. `integrated_system` 已存在于 Entitlement 类型和默认范围中，但治理资源目录尚未提供对应目录数据。
4. 组织管理员不能创建本组织安装实例。
5. 创建安装实例时尚未强制校验组织的 `integrated_system` 权益范围。
6. KY App 管理接口没有统一返回服务端计算的 `allowedActions`。
7. 凭据签发可承担轮换，但缺少面向页面的轮换结果和旧凭据收口状态聚合。
8. 版本升级/回滚没有独立编排接口；当前只能由平台管理员手工完成外部部署后切换 `registeredDigest`。
9. 当前实例启用会把 Assignment 重写成 `everyone allow`，停用会清空规则；接入精细授权页面后会覆盖管理员已经配置的成员、部门和 Agent 范围。

### 3.4 必须补齐的前端缺口

1. 没有“业务系统”平台一级入口。
2. 没有系统目录、版本复核和发布页面。
3. 没有系统交付向导和进度页面。
4. 没有技术联系人凭据领取页面。
5. 没有组织业务系统列表和安装实例详情页面。
6. 已有健康面板错误地放在组织“计费”详情中。
7. 成员端仍使用“定制软件”作为主要称谓。

## 4. 必须遵守的开发原则

### 4.1 服务端是权限事实源

- 前端不得根据登录角色自行扩大权限。
- 列表和详情响应返回 `allowedActions`；没有返回的操作保持只读。
- 所有带 `tenantId` 的请求都在服务端重新校验组织边界。
- 组织管理员提交的 `tenantId` 必须等于其权威组织，不接受前端传入值作为授权依据。
- `system_installation` Assignment 的有效成员仍由现有 Assignment 权威链路计算。
- 实例启用/停用只改变 Assignment 资源状态，必须保留已有规则；只有删除实例才清空 Assignment。
- 新实例首次启用时创建空 Assignment，默认无人可见；组织管理员显式配置范围后成员入口和 Agent 能力才生效。

### 4.2 不复制已有状态机

- Manifest 校验继续使用 `@kaiyan/ky-app-contract`。
- 版本 digest 继续使用 JCS 规范化结果。
- 开箱继续调用 `KyAppOnboardService`，页面不逐步调用底层接口模拟开箱状态机。
- Assignment 继续使用“签名预览 → 基线校验 → 提交”链路。
- 凭据明文只从一次性 claim 接口返回。

### 4.3 页面状态与领域状态分离

产品中的版本阶段映射到现有数据，不新增重复状态字段：

| 页面阶段 | 服务端字段                                                               |
| -------- | ------------------------------------------------------------------------ |
| 已登记   | `version.status=draft` 且 `reviewStatus=not_required`                    |
| 待复核   | `reviewStatus=pending`                                                   |
| 已复核   | `reviewStatus=approved`                                                  |
| 已发布   | `version.status=published` 或 definition 的 `publishedDigest` 命中该版本 |

### 4.4 敏感数据处理

- Secret 不进入日志、审计、URL 查询参数、localStorage、sessionStorage、React Query 持久缓存或错误上报。
- claim 页面从 URL 捕获票据后立即用 `history.replaceState` 清理票据。
- claim 响应设置 `Cache-Control: no-store`；前端离开页面即清空内存。
- 平台管理员和组织管理员只能看到凭据元数据，不能代领明文。
- 下载 `.env` 文件必须二次确认，文件名不得包含凭据、组织名或手机号。

### 4.5 导航只有一个事实源

- 治理路由只登记在 `web/src/lib/governanceNavigation.ts`。
- 配置/分析导航只登记在 `web/src/lib/managementNavigation.ts`。
- 组织页面 renderer 只登记在 `OrganizationManagementContent.tsx`。
- 平台页面 renderer 只登记在 `AdminShells.tsx`。
- 不新增第二套路由表或通过字符串判断偷偷挂页。

## 6. P0 服务端 API 增量

### 6.1 系统详情

新增：

```http
GET /api/app-contract/v1/systems/:systemId
```

授权：平台管理员。

响应至少包含：

```ts
interface KyAppSystemManagementDetail {
  definition: KyAppSystemDefinition;
  versions: KyAppSystemVersionSummary[];
  metrics: {
    installationCount: number;
    enabledInstallationCount: number;
    unhealthyInstallationCount: number;
    capabilityCount: number;
    externalWriteCapabilityCount: number;
  };
  allowedActions: Array<
    | 'register_version'
    | 'review_version'
    | 'publish_version'
    | 'start_delivery'
    | 'disable_system'
    | 'retire_system'
  >;
}
```

实现要求：

- 在 `server/src/kyapp/routes/systems.ts` 增加路由。
- `/systems/installable` 等静态路径必须注册在 `/systems/:systemId` 之前，防止被动态参数路由吞掉。
- 聚合逻辑放入独立 service/query，不把多表拼装写进 Express handler。
- 列表接口同步返回轻量 `metrics`，禁止对每一行发起 N+1 查询。
- Manifest 明文只在详情/版本接口返回，列表只返回能力数量和风险摘要。

### 6.2 安装实例管理列表

新增：

```http
GET /api/app-contract/v1/installations?tenantId=&systemId=&status=&cursor=&limit=
```

授权规则：

- 平台管理员可跨组织查询；`tenantId` 可选。
- 组织管理员只能查询自己的组织；忽略或拒绝其他 `tenantId`。
- 普通成员禁止访问。
- 默认 `limit=50`，最大 `100`，按 `updatedAt DESC, installationId ASC` 稳定分页。

单行至少返回：

```ts
interface KyAppInstallationListItem {
  installationId: string;
  tenantId: string;
  systemId: string;
  systemName: string;
  icon: string | null;
  status: 'pending' | 'enabled' | 'disabled' | 'deleted';
  registeredDigest: string | null;
  publishedDigest: string | null;
  domainVerifiedAt: string | null;
  deliveryStatus: string | null;
  runtimeStatus: 'healthy' | 'warning' | 'failed' | 'unknown';
  lastUsageAt: string | null;
  updatedAt: string;
  allowedActions: string[];
}
```

实现位置：

- `server/src/kyapp/systems/store.ts`：增加带过滤和游标的查询方法。
- `server/src/kyapp/installations/queries.ts`：实现管理列表聚合。
- `server/src/kyapp/routes/installations.ts`：注册接口和服务端授权。

### 6.3 可安装系统目录和权益校验

扩展治理资源目录：

```http
GET /api/governance/resources/entitlement-resource-catalog?resourceType=integrated_system
```

改造：

- `server/src/routes/governanceResourceCatalogRoutes.ts` 注入 KY App system store/query。
- 只返回 `published` 系统。
- `resourceId=systemId`，`label=system name`，`version=definition.version`。

新增组织可安装列表：

```http
GET /api/app-contract/v1/systems/installable?tenantId=:tenantId
```

返回平台已发布并且命中该组织 `integrated_system` Entitlement 范围的系统。组织管理员只允许查询本组织。

修改 `POST /installations`：

- 平台管理员保持现有能力。
- 组织管理员只能为本组织创建安装实例。
- 组织管理员安装前必须同时满足：组织 Entitlement 有效、系统 `published`、`integrated_system` 范围允许该 `systemId`、技术联系人是本组织有效成员。
- 任一权限依赖不可用时 fail-closed，不得默认为允许。
- 平台管理员代管时也记录目标组织和操作人审计。

同步修改 `KyAppInstallationService.syncAssignments()`：

- 新实例首次启用：建立空 Assignment 集合并标记资源 `enabled`，不再自动写入 `everyone allow`。
- 已有实例启用/停用：保留 `existing.assignments`，只更新资源状态。
- 删除实例：清空 Assignment 并标记资源 `disabled`。
- 现存已经是 `everyone allow` 的实例不做批量收窄，避免无授权依据地改变线上访问；由组织管理员后续显式调整。
- 开箱完成只代表基础设施可用，不代表成员已授权；交付清单必须增加“组织授权范围待配置/已配置”。

### 6.4 管理详情动作

扩展现有：

### 6.5 凭据轮换

P0 复用现有 `POST /installations/:iid/credentials` 签发新凭据，不新增另一套密钥写入逻辑。

页面流程：

```text
查看现有凭据元数据
→ 确认发起轮换
→ 签发一次性领取票据
→ 技术联系人领取并装配
→ 业务系统 credential-ack
→ 服务端撤销被替代凭据
→ 页面读取元数据确认旧凭据 revoked、新凭据 active
```

现有签发响应已经包含 `credentialId`、`keyVersion`、`ticket`、`ticketExpiresAt`、`ackDeadlineAt` 和 `expiresAt`。如页面还需要区分首次签发和轮换，只增加非敏感的 `rotation` 字段：

```ts
{
  credential: {
    credentialId: string;
    keyVersion: string;
    ticket: string;
    ticketExpiresAt: string;
    ackDeadlineAt: string;
    expiresAt: string;
    rotation: boolean;
  }
}
```

不得把明文服务凭据返回给发起轮换的管理员。

### 6.6 版本切换与回滚

P0 不负责部署业务系统代码。页面只负责以下受控步骤：

1. 展示目标发布 digest。
2. 提示技术联系人先部署对应版本。
3. 轮询 `runtime.manifestDigest` 和 `readyStatus`。
4. 两者满足后调用 `POST /installations/:iid/registered-digest`。
5. 切换后重新诊断并读取 `digestConsistent`。

回滚使用同一接口，但必须先确认业务系统已经恢复旧版本并上报旧 digest。未观测到目标 digest 时服务端继续拒绝切换。

### 6.7 错误合同

新增接口沿用 KY App 错误结构：

```ts
interface KyAppApiError {
  ok: false;
  error: {
    code: string;
    message: string;
    retryable: boolean;
    requestId: string;
  };
}
```

前端必须按 `code` 处理，禁止依赖中文 message 判断逻辑。至少覆盖：

- `invalid_input`
- `unauthorized`
- `forbidden`
- `not_found`
- `conflict`
- `review_required`
- `system_not_published`
- `entitlement_denied`
- `domain_verification_failed`
- `unavailable`

## 10. 端到端验收数据与步骤

### 10.1 固定测试身份

- 平台管理员 A：登记和发布人。
- 平台管理员 B：敏感版本复核人。
- 组织管理员 OA：目标组织管理员。
- 技术联系人 TC：目标组织有效成员。
- 普通成员 U1：被授权。
- 普通成员 U2：未授权。
- 组织管理员 OB：另一个组织，用于越权测试。

### 10.2 固定测试资源

- 系统：`e2e-business-system`
- v1：只读能力，发布无需人工复核。
- v2：增加 `external_write` 能力，必须触发双人复核。
- 安装实例：`e2e-business-system-tenant-a`
- 测试组织：`tenant-a`
- 越权组织：`tenant-b`

### 10.3 标准验收流程

```text
平台管理员 A 上传 v1 Manifest
→ 校验通过并发布
→ 为 tenant-a 启动交付
→ TC 登录领取并装配凭据
→ 业务系统 credential-ack
→ 配置并验证 DNS TXT
→ 业务系统 live/ready 上报 v1 digest
→ 继续交付直至 completed
→ OA 将安装实例授权给 U1 和指定 Agent
→ U1 打开业务系统并完成握手
→ U1 在 Agent 中调用只读能力
→ U2 看不到业务系统且工具快照中没有该能力
→ 管理员 A 上传 v2
→ 管理员 B 复核后发布
→ 外部系统部署 v2 并上报 digest
→ 平台切换 registeredDigest
→ 诊断、运行、审计和用量全部回读
```

### 10.4 验收证据

必须保存：

- 页面截图：系统目录、版本差异、复核、交付进度、领取完成、Assignment 影响预览、运营健康。
- HTTP 证据：关键请求状态码、`requestId`、非敏感响应摘要。
- 数据库只读回读：definition、version、installation、credential metadata、assignment、delivery、audit。
- 成员侧证据：U1 成功、U2 拒绝。
- Agent 能力证据：新会话工具快照包含/不包含目标能力。
- 业务结果：真实只读能力返回预期业务数据。

CI、构建成功、HTTP 200 和健康检查不能替代成员权限与真实业务能力验收。

- 导航和新页面可通过回滚对应前端提交撤销，不影响已有 `/apps` 成员入口。
- 新增查询接口可保留，不影响旧客户端。
- 不删除旧 KY App 表或历史审计。
- 已发布系统版本不可删除或覆盖；业务回滚通过恢复旧外部版本后切换 `registeredDigest`。
- 已领取凭据不能通过回滚代码恢复明文；需要重新签发并走轮换。
- 已执行离场不能自动恢复被吊销凭据；重新接入必须创建新凭据，必要时创建新安装实例。

## 12. P1：低改造系统接入

P0 真实验收完成后再启动。

### 12.1 领域模型

新增系统接入模式：

```ts
type IntegrationMode = 'ky_app' | 'page' | 'mcp' | 'openapi' | 'rest' | 'browser';
type PageOpenMode = 'iframe' | 'external' | 'auto';
```

实现前先形成 ADR，明确这些字段属于 Manifest v2、平台侧包装 Manifest，还是独立 integration profile。不得直接向 v1 JSON Schema 塞可选字段而不升级契约版本。

### 12.2 工作包

- P1-WP1：页面 URL、iframe/external/auto 和 CSP/X-Frame-Options 探测。
- P1-WP2：MCP 服务绑定和能力选择。
- P1-WP3：手工 REST endpoint、method、input/output schema 配置。
- P1-WP4：OpenAPI 导入、operation 选择和工具命名冲突检查。
- P1-WP5：组织共享凭据绑定；凭据继续引用治理 credential，不在 Manifest 保存 secret。

### 12.3 P1 完成标准

- 旧系统无需接入完整 KY App SDK，也能以页面或 API 能力形式进入目录。
- 页面和能力可独立启停。
- iframe 不可用时 `auto` 明确降级到新窗口。
- 模型无法控制 host、method、header、secret 或身份字段。
- 写操作仍经过风险分级和确认。

## 13. P2：个人身份和 OpenAPI

### 13.1 工作包

- P2-WP1：个人连接资源模型和加密存储。
- P2-WP2：OAuth Authorization Code + PKCE。
- P2-WP3：个人 Token 一次性录入。
- P2-WP4：`个人设置 → 连接与授权` 系统连接卡。
- P2-WP5：工具快照根据个人连接状态 fail-closed。

### 13.2 安全门禁

- OAuth state、nonce、PKCE verifier 必须短期、单次使用并绑定当前用户和组织。
- Secret 永不回显。
- 断开或过期后相关能力必须从新会话工具快照移除。
- 组织管理员不能代替成员授权个人账号。
- 外部账号 ID 由服务端绑定，模型不能传入。

### 13.3 P2 完成标准

- 用户可以连接、重新授权和断开自己的业务系统账号。
- 未连接、过期、撤销或 scope 不足时，相关能力不可调用。
- 另一个用户、组织或 Agent 无法复用该个人连接。

## 14. P3：浏览器、上下文和移动端

### 14.1 工作包

- P3-WP1：受控浏览器会话和域名白名单。
- P3-WP2：页面当前单据安全摘要协议。
- P3-WP3：多 iframe LRU 保活和内存上限。
- P3-WP4：移动端 WebView/外部浏览器策略。
- P3-WP5：跨端深链、返回和重新鉴权。

### 14.2 P3 完成标准

- 页面只向 Agent 提供声明过、用户确认过的安全摘要。
- Cookie、Token、整页 HTML 和未声明字段不进入模型上下文。
- 浏览器自动化只能访问白名单域名和允许动作。
- 移动端不因 WebView 不兼容而出现空白页，必须有外部浏览器降级。

## 15. 开发完成定义

单个工作包只有同时满足以下条件才算完成：

- 代码实现完成，没有模拟数据和不可达按钮。
- 类型检查、受影响测试和模块测试通过。
- 所有读取、写入和越权场景有服务端测试。
- 页面具备 loading、empty、error、retry 和无权限状态。
- 写操作具备确认、冲突处理、审计和成功后权威回读。
- 文档、路由、API 和实际实现一致。
- Git 提交范围清晰，工作区无意外文件。

整个 P0 只有在真实浏览器、真实 HTTP、PostgreSQL 回读、成员权限和至少一个真实只读能力全部验收后才算交付完成。
