管理当前用户的定时任务与任务看板。target 默认 cron：支持 list/create/update/delete/run。target=taskboard 时，普通会话按当前登录用户、租户、看板角色及服务端 allowedActions 访问；支持 board/task/comment/execution/integration 资源 action、分页查询、CAS 写入、任务派发和人工集成批次。由任务看板派发的 Execution 会按 Run/Session 反查当前任务和职责，可读取当前任务的全量或增量上下文、写入 Agent 进展并携带 context receipt 提交结构化 resolution；不能伪装成普通管理会话、扩大仓库权限或绕过工作流。普通 Delivery Work 登记唯一非 Draft PR 后必须调用 execution.pull_request.inspect，等待当前精确 head 的权威 CI 全绿并重新读取 context；失败 job 可用 receipt 中的 inspectionId/providerJobId 调用 execution.pull_request.log 受控读取日志。Review 必须独立 inspect 当前 head/base/subject 与 CI 后再记录 reviewed subject；pending、failure、unknown、receipt 缺失或 head 漂移均由服务端失败关闭。Merge 使用 integration.source.inspect 再次读取 Provider，失败 job 用 integration.source.log 受控读取，最终 merge 门禁要求当前 Merge Execution 的 receipt 且不复用早期快照。Workflow v3 Integration Work Execution 创建直接父提交后必须调用 execution.integration_candidate.push（只传 commitOid），不得执行 git push；受控 push 成功后才能提交 ready_for_review。Review/Merge Runtime 不接收通用 GitHub 写凭据；外部写操作只能使用阶段专用受控 action。work、review、merge 的允许结果由同一个 workflow contract 决定；服务端校验 task version、change sequence、policy revision、contract digest、reviewed subject 和绑定 execution/task/PR/headOid 的 inspection receipt。组织看板角色为 viewer/editor/maintainer/owner：viewer 只读，editor 及以上可评论和触发，人工集成批次需 maintainer/owner。cron 与 taskboard 只读 action 无需审批；可逆看板写操作按 workspace_write 审批，派发、评论删除、integration 授权与 cron 写操作保持高风险审批。
