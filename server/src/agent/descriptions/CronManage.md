管理当前用户的定时任务与任务看板。target 默认 cron：支持 list/create/update/delete/run。target=taskboard 时，普通会话按当前登录用户、租户、看板角色及服务端 allowedActions 访问；支持 board/task/comment/execution/integration 资源 action、分页查询、CAS 写入、任务派发和人工集成批次。

任务看板 Execution 会按 Run/Session 反查当前任务和职责。execution.context 读取当前任务上下文；execution.pull_request.set 登记当前 Delivery 唯一的非 Draft PR（没有有效 PR 时才创建，禁止重复），inspect 读取已登记 PR 的 head/base、checks 和 workflow，log 读取 observed workflow 的 job 日志；integration.sources 读取 Integration 的冻结来源。当前职责完成或确实需要人工时，只使用 execution.finish({targetStatus, body}) 原子写入可验证交接，不接受旧 status 字段。

组织看板角色为 viewer/editor/maintainer/owner：viewer 只读，editor 及以上可评论并触发；人工集成批次需 maintainer/owner。评论读取：最近一条用 `comment.get({taskId})`（缺省 ordinal=-1），最近 N 条用 `comment.list({taskId, latest:N})`，第 N 条用 `comment.get({taskId, ordinal:N})`（负数为倒数第几条），也可 `comment.list({taskId, ordinal:N})`。评论多时先 `comment.list({taskId, view:"digest", order:"desc", pageSize:50})` 扫最近的目录行，再按 ordinal 或 commentId 取全文，不要整表回读；latest/ordinal/commentId 存在时 order 与 page 被忽略，返回恒为时间升序。execution.context 默认 commentMode="recent"、commentLimit=1，只给最近一条评论全文，更早的是目录行（bodyTruncated=true，附 ordinal 与 bodyChars），需要更多时显式传 commentLimit 或 commentMode="full"。旧 list action 也只回最近 5 条评论。ordinal 随评论删除漂移，跨轮引用用 commentId。cron 与 taskboard 只读 action 无需审批；看板写操作仍按平台统一风险策略处理。
