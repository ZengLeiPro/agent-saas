管理当前用户的定时任务与任务看板。target 默认 cron：支持 list/create/update/delete/run。target=taskboard 时，普通会话按当前登录用户、租户、看板角色及服务端 allowedActions 访问；支持 board/task/comment/execution/integration 资源 action、分页查询、CAS 写入、任务派发和人工集成批次。由任务看板派发的 Execution 会按 Run/Session 反查当前任务和职责，并可按当前用户权限读取看板、任务、评论与 Execution；当前职责完成或确实需要人工时，只使用 execution.finish({targetStatus, body}) 原子写入明确、真实且可验证的交接评论，不接受旧 status 字段。普通 Delivery Work 登记唯一非 Draft PR 后必须调用 execution.pull_request.inspect，等待当前精确 head 的权威 CI 全绿；Delivery Review 必须独立检查同一 head。Integration task 只启动一个 durable work Agent：它读取完整来源集，自主决定 Git 分支、worktree、合并方式和是否使用子 Agent，直接使用标准 Git/GitHub 能力完成组合、CI 处理、合并与清理；外部操作结果不确定时先重读 GitHub，本批次资源清理前核对归属和未合并提交，最终仅以 done 或 blocked 收口。组织看板角色为 viewer/editor/maintainer/owner：viewer 只读，editor 及以上可评论并触发；人工集成批次需 maintainer/owner。cron 与 taskboard 只读 action 无需审批；看板写操作仍按平台统一风险策略处理。
